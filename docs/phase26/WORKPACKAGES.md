**작업**

## M1 · 도면·PDF 페이지 예산 (P26-A01~A05)

**확인된 사실** — `buildDetailDrawings`의 기본값은 `maxPages=60`이고 현재 도면은 여기에 정확히 도달한다(`count=60 max=60`). 한도를 600으로 올리면 A01~A04는 통과한다. 반면 `drawingWorker`는 이미 `maxPages:600`을 쓴다. 즉 **worker 경로는 이미 넓혀졌고 기본값만 남아 있다.**

**결정할 것**
- 기본값을 worker와 맞출 것인가, 호출자마다 명시할 것인가.
- A05(`PDF_PAGE_LIMIT`)는 `vectorPdf`의 별도 60쪽 하드 제한이다. 한도를 올릴지, 문서를 분할할지 별도 판단이 필요하다. 한도는 메모리·응답 크기를 묶는 장치이므로 근거 없이 올리지 않는다.

**작업**
1. 두 한도의 존재 이유(메모리·응답 크기·실행 시간)를 코드와 기존 결정 기록에서 확인한다.
2. 결정을 `docs/phase26/adr/ADR-001-PAGE-BUDGET.md`로 남긴 뒤 적용한다.
3. 한도를 올린다면 실제 상한에서의 메모리·시간을 측정해 증거로 남긴다.

**완료 조건** — A01~A05 통과. 한도 변경분에 대해 측정 근거가 있다. 상한을 없애지 않는다.

## M2 · 낡은 기준선 (P26-B01~B08)

**작업**
1. 항목마다 **기록값과 현재값의 차이를 먼저 출력**한다.
2. 차이가 버전 문자열·식별자처럼 판정에 영향이 없으면 갱신한다.
3. 차이가 수치 판정·검사 개수·공개 표면을 바꾸면 갱신하지 않고 원인을 조사한다.
4. `P26-B03`은 `buildAgentManifest()`의 **공개 API 기준선**이다. 도구·API 추가/삭제/이름변경을 한 줄씩 검토하고, 의도된 변경임을 확인한 뒤에만 갱신한다. 의도치 않은 표면 변경은 부채가 아니라 결함이다.

**완료 조건** — B01~B08 통과. 각 갱신에 "무엇이 왜 달라졌는지" 한 줄 근거가 붙는다.

## M3 · 계약 불일치와 거버넌스 판정 (P26-C01, E01~E02)

**P26-C01** — 취소 경로가 `loadFont`를 호출하지 않아 테스트가 resolver를 못 받는다. 먼저 **어느 쪽이 맞는지** 정한다. 취소 시 폰트를 로드하지 않는 것이 의도된 최적화라면 테스트를 계약에 맞추고, 의도치 않은 회귀라면 코드를 고친다. 판단 없이 테스트만 통과시키지 않는다.

**P26-E01** — SB1 봉인 build-lock r1이 현재 소스 해시와 다르다. `verification/**`는 `-text` 봉인 증거다. r1을 덮어쓰지 않는다. 저장소가 이미 쓰는 개정 관례(`source-locks-r2`, `-r2.json`)에 따라 **r2 발행 제안서**를 만들어 오너 승인을 받는다. 승인 전까지 `DEFERRED`.

**P26-E02** — 설계검토가 NG 검사를 하나도 만들지 않는다. Phase24/25에서 "NG"와 "미검토"가 분리된 결과일 가능성이 높다(`m6-rc-design`과 같은 부류). 의도된 의미를 먼저 확정하고 기대치를 맞춘다.

**완료 조건** — C01 통과. E01·E02는 통과하거나, 사유가 적힌 `DEFERRED`로 등록된다.

## M4 · 구조 부채 (P26-S01~S05)

- **S01 재현성** — `P17-M0` 증거가 `.gitignore`된 `tmp/` 파일을 해시로 고정한다. 새 클론에서는 반드시 실패한다. 지금은 손으로 복원해 둔 상태다. 증거가 추적 가능한 경로만 가리키도록 바꾸거나, 없을 때 명시적 blocker로 떨어지게 한다. **조용히 건너뛰게 만들지 않는다.**
- **S02 만료 정책** — 호환성 정책 기한이 P9-M9/P9-M10인데 작업 공간은 Phase 25를 지났다. `p20-module-audit`이 `compatibilityGoverned`를 면제 중이다. 정책을 갱신하거나 정식으로 연장하고, 면제가 필요 없게 만든다.
- **S03 검사 공백** — `phase9M1.js`만 importer가 없다. 보관 증거 생성기이므로 삭제가 기본값이 아니다. 검사를 붙이거나, 생성기임을 명시하고 등록한다.
- **S04 계약 표기** — manifest가 레거시 RC 보고서 버전을 광고하는데 제품은 p25 버전을 낸다. manifest 해시 안정성을 고려해 변경 여부를 정한다.
- **S05 경로 비대칭** — 구속력 항이 Direct P-Delta 잔차에는 필요하고 1차 잔차에서는 이중 계산된다. 두 경로의 반력 규약이 다르기 때문이다. 통일하거나, 왜 다른지 코드에 남긴다.

**완료 조건** — 각 항목이 해소되거나, 사유와 함께 `DEFERRED`로 등록된다. S01은 반드시 해소한다.

## M5 · 정식 게이트 확장 (P26-S06) ★

**이 페이즈의 존재 이유.**

**작업**
1. phase 16~25 검사를 정식 게이트에 편입한다. phase 7~15처럼 러너를 두고 `npm test` 사슬에 붙인다.
2. `rc-engineering` 11건은 대장에서 `DEFERRED`인 항목을 읽어 **사유와 함께 제외**한다. 러너가 제외 목록을 출력하도록 해, 몇 건이 왜 빠졌는지 실행할 때마다 보이게 한다.
3. 제외 목록은 대장 하나만 고치면 바뀌도록 한다. 코드에 검사 이름을 흩뿌리지 않는다.
4. 실행 시간을 측정한다. 전체가 지나치게 길어지면 사슬을 나누되 **기본 `npm test`가 phase 16~25를 포함한다**는 조건은 유지한다.

**완료 조건** — `npm test` 통과. 출력에 제외 건수와 사유가 보인다. `DEFERRED` 항목을 하나라도 되살리면 게이트가 빨개진다(제외가 영구 은폐가 되지 않는다).

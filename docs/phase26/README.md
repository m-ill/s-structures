# Phase26 — 기술부채 정리와 정식 게이트 확장

2026-09-13 · 계획 v1 · **착수 전 / 구현 미시작**

기준 커밋 `a2675a62`. 이 페이즈는 새 기능을 만들지 않는다. 정식 검사(`npm test`) 밖에서 방치되어 쌓인 부채를 정리하고, 같은 일이 반복되지 않도록 게이트 범위를 넓히는 것이 전부다.

## 왜 필요한가

`npm test`는 마일스톤과 phase 7~15만 실행한다. phase 16~25는 코드가 있는데도 정식 게이트 밖에 있었고, 그 사이 검사 27건이 깨진 채로 남았다. 게이트를 넓히지 않으면 정리해도 같은 상태로 돌아간다.

부채 33건을 [대장](DEBT_REGISTER.json)에 기록했다. 전부 기준 커밋에서 실제로 재현한 것이며 추정 항목은 없다.

| 묶음 | 건수 | 성격 |
| --- | --- | --- |
| `page-budget` | 5 | 도면·PDF 기본 페이지 한도를 현재 산출물이 넘어섬 |
| `stale-baseline` | 8 | 기록된 기준선이 현재 코드보다 뒤처짐 |
| `contract` | 2 | 광고된 계약과 실제 동작 불일치 |
| `governance` | 3 | 봉인 증거·만료 정책 등 오너 판단이 필요한 항목 |
| `reproducibility` | 1 | 새 클론에서 재현 불가 |
| `coverage` | 1 | 검사 없는 모듈 |
| `gate` | 1 | 게이트 범위 자체 |
| `rc-engineering` | 11 | **미구현 기능 — Phase27로 이관** |

## 범위 경계

**Phase26이 하는 것**: 위 22건. 기존 동작을 바꾸지 않고 기록·계약·범위를 현재 코드에 맞춘다.

**Phase26이 하지 않는 것**: `rc-engineering` 11건. 비틀림 종방향 분배, 이음 바 매핑 전략, 후프 폐합, 자동 접합 상세는 구조설계 판단이 필요한 신규 구현이다. 부채 정리로 포장하지 않고 [Phase27](../phase27/README.md)로 넘긴다.

이관 항목은 **삭제하거나 skip 처리하지 않는다.** 미구현 사유를 명시한 등록 상태(`DEFERRED`)로 남기고, 게이트에서는 사유와 함께 제외한다. 이 저장소가 기존에 쓰는 `release-blocked`·명시적 blocker와 같은 방식이다.

## 원칙

- 정상 동작하는 코드는 이유 없이 다시 쓰지 않는다. 부채 정리는 최소 변경으로 한다.
- 기록을 코드에 맞출 때, 숫자 판정이 바뀌는지 항목별로 확인하고 바뀌면 갱신하지 않고 보고한다.
- 봉인 증거(`verification/**`는 `-text`)는 덮어쓰지 않는다. 필요하면 개정본을 새로 발행한다.
- 테스트를 통과시키려고 검사 범위를 줄이지 않는다. 기대치를 고칠 때는 무엇을 검증하는지 유지한다.

## 완료 판정

M5까지 끝나고 `npm test`가 phase 16~25를 포함한 상태로 통과하면 Phase26 구현 완료다. `rc-engineering` 11건이 `DEFERRED`로 남아 있는 것은 완료 조건에 어긋나지 않는다. 다만 **제품 자격이나 설계 적합성을 뜻하지 않는다.**

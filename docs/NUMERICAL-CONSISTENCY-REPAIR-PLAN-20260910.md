후속 사용자 요청에 따른 실행 정본은 [Phase21 M0~M7 개발계획](archive/phase21/README.md)이다. **M0 강체 다이어프램 Direct 구현을 먼저 수행**하고 RC 수치·입력·결과·보고서·메모리·복구를 이어서 수정한다. 이 문서의 결함 심각도·관측값은 보존하며, 아래 N0~N6는 당시 제안 순서로서 Phase21 순서로 대체됐다.

## 결론

최우선 결함은 RC 정사각형 단면의 높이 해석 오류다. 400×400 기둥을 설계 모듈이 400×600으로 계산해 휨·전단 내력을 과대평가한다. 그 다음은 선택 조합과 화면 수치의 불일치, 화면 이동에 따른 설계조건 덮어쓰기다. 기존 예비 설계 보고서는 **결함 재현 자료**로 보존하고, 수정 후 새 입력·결과 식별자로 다시 검증해야 한다. 현재 수치를 최종 설계 적합성 근거로 재사용하지 않는다.

검증 대상 배포 commit은 `fefde822ae27a024ea8a834642b8aac10a24bd77`이다. 사용자 요청에 따라 실제 공개 프로그램에서 24절점·39부재·138하중·20조합 모델을 실행했다. 정적 20케이스와 모달은 완료했고, 강체 다이어프램이 있는 Direct P-Delta X/Y는 차단됐다. 실행 기록의 입력 hash는 `5b1c2cb3917cced2b1600833f15f4d36c9f55ee708b9a87ef85282f7b4b10076`, 예비 보고서 snapshot hash는 `4bddb0561cbe307780bb137446c91329d9d1977a1bc7ef50d352595a8e33f452`다.

전체 시험 자료: [RUN-001](../output/reports/design-workflow-pilot-20260910/run-001/PROTOCOL.md). 전체 HTML 보고서 1,341,046자를 확보했다. 세션 초기화로 원래 JSON·CSV 수집은 중단됐으므로 완전본으로 취급하지 않는다. HTML의 5,940개 표 행을 별도 추출한 CSV·JSON에는 파생 자료임을 표시했다.

## 1. P0 / 확정: 400×400 기둥의 RC 설계 높이가 600 mm로 바뀜

**관측·재현**

- `rcsq400`은 `shape=SQUARE`, `dims.B=400`, 실제 해석 단면 `B=H=0.4 m`, `A=0.16 m²`다. 정사각형 입력에는 `dims.H`가 없다.
- [concrete.js](../src/design/concrete.js)의 `concreteSectionProps`는 `dims.H`가 없으면 600 mm를 사용한다. 따라서 설계용 b/h는 0.4/0.6 m인데 축력 계산용 Ag는 0.16 m²인 모순이 생긴다.
- 실제 보고서의 기둥 휨내력 555.39 / 337.365 kN·m와 같은 값을 독립 함수 호출로 재현했다.
- 동일 재료·철근비·피복·예비 식에서 정사각형 높이만 400 mm로 정규화하면 두 축 모두 224.91 kN·m다. 한 축은 약 2.469배, 다른 축은 1.5배 과대평가됐다. 이것은 **치수 오류의 민감도 비교**이며 수정된 건물 전체 결과나 최종 설계 내력을 뜻하지 않는다.

**수정 방법**

1. 해석·설계가 공유하는 정규화된 단면 치수 계약을 사용한다. `SQUARE: H=B`, `RECT: B/H 필수` 등 형상별 의미와 mm/m 변환을 한곳에서 결정한다.
2. 불명확한 형상에 300×600 기본값을 조용히 넣지 않는다. 치수 없음·지원 형상 아님은 `INPUT_REQUIRED` 또는 `UNSUPPORTED`로 차단한다.
3. 정규화된 b×h와 Ag의 일치, 단면 축과 물성의 일치를 확인한다. 실제 형상·단면 수정자·단면적 override는 출처를 따로 보존한다.
4. 영향받은 RC 설계 결과를 모두 무효화한다. 해석 물성도 바뀌는지 확인한 뒤 재해석 필요 범위를 정하고, 최소한 전체 부재 설계 검토·보고서는 재생성한다.

**완료 조건**

- 정사각형 300/400/500 mm의 양축 내력이 같은 입력 조건에서 일치한다.
- SQUARE B400과 RECT B400/H400의 설계 결과가 일치한다.
- 단면 90도 회전 시 양축 결과가 교환되고, 강성·설계 치수가 달라지지 않는다.
- 누락 치수·0·null·비수치 입력이 내력 0/검정비 0의 OK로 바뀌지 않는다.
- 해당 파일로 재현: `node output/reports/design-workflow-pilot-20260910/run-001/probe-rc-square.mjs`.

근거: [단면 함수 재현 JSON](../output/reports/design-workflow-pilot-20260910/run-001/calculations/rc-square-section-probe.json).

## 2. P1 / 확정: 선택 조합의 이름에 포락 수치를 표시

**관측·원인**

- `MAX-WX-N` 화면은 최대변위를 **9.426 mm**로 표시했다. 같은 조합의 보존된 보고서 값은 **3.653495 mm**다.
- `ULS-G2` 화면에서도 **9.426 mm**가 관측됐지만 보고서의 해당 조합 값은 **2.003886 mm**다.
- [elasticResultVisualization.js](../src/ui/elasticResultVisualization.js)의 `staticView`는 선택 조합을 전달하지 않고 `pickStaticResult(payload)`를 호출한다. 이 함수는 `payload.envelope`를 조합별 결과보다 먼저 사용한다. 따라서 이름과 수치의 연결이 끊긴다.
- 포락 변위 성분은 서로 다른 조합에서 나올 수 있다. 이를 단일 조합의 변형 형상처럼 연결해서 보여주면 물리적으로 존재하지 않는 형상을 만들 수 있다.

**수정 방법**

- `(analysisRunId, inputHash, method, comboId)`로 결과를 명시적으로 선택한다. 선택 조합이 없으면 오류를 표시하고 포락·첫 성공 조합으로 대체하지 않는다.
- 포락은 사용자가 선택한 별도 모드로 제공한다. 값마다 지배 조합을 표시하고, 동시 발생하지 않는 성분을 단일 변형 형상으로 표시하지 않는다.
- 변위·부재력·반력·검정·보고서가 동일한 선택 결과를 참조하도록 공통 결과 준비 객체를 사용한다.

**완료 조건**

- 값이 명확히 다른 중력·X풍·Y풍 조합을 번갈아 선택해 표·SVG·상단 수치·보고서가 일치하는지 확인한다.
- 누락/실패 조합 선택 시 이전 그림과 수치가 제거된다. 이전 모달 결과가 실패한 P-Delta 선택 아래 남지 않는다.
- 원시 변위 m → 화면 mm는 정확히 한 번 변환한다. 허용오차는 원시값 비교와 표시 반올림 비교로 분리한다.

## 5. P1 / 별도 검증 후 수정: RC 전단 축 대응과 배근 계약

`shearZ`는 Vz에 `bz/dz`, `shearY`는 Vy에 `by/dy`를 사용한다. 휨 함수에서는 `bz/dz`가 Mz에, `by/dy`가 My에 대응한다. 전단 Vy와 휨 Mz, 전단 Vz와 휨 My의 부재 축 계약에 맞는지 비정사각형 단면과 90도 회전 시험으로 확정해야 한다. 정사각형 치수 오류와 섞어서 한 번에 숫자를 고치지 않는다.

현재 전단 검토식은 `Vu / phiVc`이며 제공한 스터럽 Vs를 반영한 완성된 단면 설계가 아니다. BX11의 1.83은 이 예비 검토의 값이다. 단면·축 오류 수정 후 재계산하고, 실제 배근 입력·철근 기여분·규칙 적용범위를 추가해야 한다. 지금 1.83을 곧바로 최종 철근콘크리트 설계 실패 또는 단순 반올림 오류로 단정하지 않는다.

추가 확인: 인장/압축 부호, 동시 발생 P-M 조합, 철근비/철근량/유효깊이 계약, null·0 입력 처리. 검증되지 않은 항목은 새 결함으로 확정하지 않는다.

**완료 조건**: 보고서·UI·WebMCP의 동일 필드와 단위 일치. 실패 시 결과 사용 차단. 입력/배포/규칙 변경 시 기존 결과의 stale 판정 일치.

## 7. P-Delta는 별도 기능 완성 과제

이번 X/Y 실패 원인은 `DIRECT_PDELTA_RIGID_DIAPHRAGM_UNSUPPORTED`다. [secondOrder.js](../src/solver/pdelta/secondOrder.js)의 `directCompatibility`가 강체 다이어프램을 명시적으로 차단한다. 반복 횟수나 수렴 오차 조정으로 해결할 문제가 아니다.

강체 다이어프램의 변환 T를 이용해 탄성강성·기하강성·하중/잔차를 같은 축약계로 처리하고, 같은 변환으로 변위·부재력·지점 반력을 복원해야 한다. 개념적으로 `Kr = Tᵀ(Ke + Kg)T`, `rr = Tᵀr`의 일관성을 보장한다. 이 수식만 추가하면 완성되는 것이 아니라 반복 중 기하강성 갱신·구속 일·전체 평형을 함께 검증해야 한다.

**수정·검증 순서**

1. 입력 단계에서 미지원 조건과 영향받는 다이어프램 ID를 보여준다. 현재의 일반적인 ANALYSIS_NOT_COMPLETED보다 구체적인 원인을 전달한다.
2. 다이어프램이 없는 기존 Direct 회귀를 유지하고, 축약계 구현을 별도 테스트로 추가한다.
3. 대칭 1층 → 3층 → 편심/비틀림 → 임계하중 접근 사례로 확장한다. P→0의 1차해석 극한, 다이어프램 강체운동 구속, 6성분 평형, 독립 수치 기준과 비교한다.
4. 강체 다이어프램을 삭제하거나 큰 가상 강성으로 바꿔 통과시킨 결과를 원래 구조의 검증으로 간주하지 않는다.

코드상 부재 단부 release, tensionOnly/compressionOnly, 0강성 연결 스프링도 별도 Direct 차단 조건이다. 이는 코드 확인 결과이며 이번 모델에서 모두 시험한 것은 아니다. 양의 연결 스프링도 기하강성 근사 제한이 있으므로 지원표를 함께 관리한다.

## 정상으로 확인한 사항과 확정하지 않은 사항

- 자중 입력 합계 1,220.328 kN과 반력 합계 1,220.3279999999995 kN이 일치했다. 차이는 약 4.55×10⁻¹³ kN이다. 이것은 수정할 수치 오류가 아니다.
- D 최대변위 1.390754 mm와 1.4D의 1.947055 mm는 선형 비례를 만족한다. 전체 수치 모듈이 모두 틀렸다고 결론내리지 않는다.
- 약 2×10⁻¹⁵ kN의 직렬화 차이는 부동소수점 반올림 범위다. 임의 반올림으로 설계값을 맞추지 않는다.
- 모달 1차 주기 0.4184 s, X 참여율 90.66%가 화면에 나타났고 완료 기록을 확보했다. 독립 모달 기준값과 전체 비교를 완료한 것은 아니다.
- 세션 초기화 원인은 미확정이다. 보고서 16개 동시 조각 조회 중 발생했지만 메모리 문제·브라우저 수명주기 등을 계측하기 전 원인을 단정하지 않는다.

## 구현 순서와 인수 기준

| 순서 | 작업 | 인수 기준 |
|---|---|---|
| N0 | 기존 증거 잠금·최소 재현 고정 | 실패 전 입력·원시 결과·보고서·화면·hash 보존 |
| N1 | 정사각형 단면 치수 계약 | 정사각형/동일 RECT 동등성, 양축 대칭성, 오류 입력 차단 |
| N2 | 선택 조합 및 실패 화면 연결 | 조합별 원시값·UI·보고서 일치, 포락 명시, 이전 결과 제거 |
| N3 | 화면 조회의 입력 불변성 | 단계 왕복 hash 불변, 명시적 적용만 변경 |
| N4 | RC 축·역할·집계·요약 계약 | 회전 시험, N/A 분리, 중복 제거, 보고서 완전성 |
| N5 | Direct 다이어프램 지원 | 축약계·반력 복원·평형·독립 기준·기존 회귀 통과 |
| N6 | 같은 3층 모델 전체 재검증 | 새 결과와 기존 결함 자료 비교, 화면별 캡처, 완전한 보고서 저장·복원 |

이번 문서 작성에서는 제품 소스 수정·병합·배포를 하지 않았다. 재현용 계산과 표 재집계만 수행했다. 기능 미지원·설계 가정 미확정·수치 결함을 분리하고, 수정 후 전체 검토 수치가 달라질 수 있음을 보고서에 유지한다.

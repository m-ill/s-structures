## Environment

- 배포 형태 B(데스크톱) 우선, A(웹) 1개 시나리오 이상 포함.
- 참가자 PC는 개발 환경이 아닌 클린 조건. 설치부터 시나리오에 포함.
- 데이터: 참가자 실제 프로젝트 사용 권장 (민감정보 처리 합의 후). 불가 시 온보딩 샘플.

## Execution Protocol

1. 시나리오당 1세션, 진행자는 관찰만. 참가자가 15분 이상 막히면 개입하되 **개입 지점 = 문서/UX 결함**으로 기록.
2. 세션 종료 즉시 리포트 작성: `reports/launch-readiness/pilot-##.md` — 템플릿: 참가자 프로필 / 소요시간 / 완주 여부 / 막힌 지점(스크린샷) / 발견 결함 / 인용 피드백 / 분류(blocker·major·minor).
3. blocker 정의: 완주 불가, 데이터 손실, 잘못된 해석·설계 결과, 보안 결함. blocker는 TD 등재→수정→**해당 시나리오 재실행**.
4. major/minor는 backlog 등재 후 출시 여부와 분리 판단 (오너 결정).

## Exit Criteria (P4-M10 종료)

1. 10 시나리오 전부 완주 리포트 존재.
2. blocker 0 (재실행 포함).
3. 종합 리포트 `reports/launch-readiness/pilot-summary.md`: 결함 통계, 반영 내역, 잔여 major/minor 목록과 오너 판단 기록.

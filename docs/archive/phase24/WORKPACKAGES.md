# Phase24 작업 패키지

> 2026-09-11 재계획: Phase24는 부분 구현 기준선으로 보존하고 미완료 범위를 [Phase25](../../phase25/README.md)로 이관했다. 아래 계획/실적은 당시 기록이며 전체 마일스톤 완료가 아니다. 현재 잔여 작업의 정본은 [32건 재점검 대장](../../phase25/GAP_AUDIT.md)이다.


2026-09-11 최초 계획 기록 · 작성 당시 모두 계획 상태. 아래 신규 모듈·시험·산출물 경로는 **구현 시 만들 제안**이며 현재 존재하거나 통과했다는 뜻이 아니다.

각 단계는 `작은 RED 확인 → 최소 구현 → GREEN → 책임 정리 → 직접 영향 시험 → 기록`으로 닫는다. 다음 단계 진입은 해당 단계의 필수 집중 시험 통과로 판단한다. 전체 회귀·실제 건물·장시간 환경 시험은 개발 단계의 진입 조건에 넣지 않는다. 전체 자격이 필요한 배포 판정은 별도다.

**모든 단계 공통 완료 조건:** 그 단계에서 추가/수정한 모듈을 WebMCP로 제어할 수 있어야 한다. [모듈별 제어 계약](WEBMCP_CONTROL_CONTRACT.md)에 맞춰 실제 definition→공통 제품 서비스→결과 경계를 연결하고 해당 T18 사례를 시험한다. 내부 함수 또는 UI만 완성한 상태는 완료가 아니다. WebMCP 등록명·schema·capability도 각 단계의 변경 기록에 포함한다.

## M0 — 기준선·규칙 범위·TDD 준비

**진입:** Phase24 계획을 기준으로 실제 구현 작업을 시작할 때.

1. 시작 커밋·작업 트리·기존 사용자 변경·Node 실행환경을 기록한다. 과거 pilot 원본을 수정하지 않고 결함별 최소 합성 입력만 추출한다. 원본 경로/커밋과 최소 입력 사이의 관계를 기록하며 원본 전체를 시험마다 읽지 않는다.
2. [TDD 결함 대응표](TDD_VALIDATION_PLAN.md)의 D01~D12를 등록한다. 우선순위는 거짓 OK 차단, 입력/버전/동시 수요 보존, 실제 내력·자동 수정, 도면 순이다.
3. 첫 RC 보·기둥·접합·독립기초의 지원 형식과 필수 검토 목록을 고정한다. 각 규칙에 기준명·판본·조항·적용 범위·단위·독립 예제를 연결한다. 기준을 확보하지 못한 규칙은 `RULE_UNAVAILABLE`로 남기며 임의 계수로 채우지 않는다.
4. 현재 규칙/trace가 예비인지 검증된 계산인지 목록화한다. 독립 단면 강도 계산을 기존 fiber 기능에서 재사용할 수 있는지 확인하되 비선형 전역해석을 RC 단면 검토의 숨은 필수 의존성으로 만들지 않는다.
5. 기존 `.mjs` 시험 관례에 맞춰 특정 milestone/시험만 선택하는 실행 도구와 작은 fixture 묶음을 준비한다. 기본 명령이 전체 시험·브라우저·실제 건물을 호출하지 않게 한다.
6. 현재 `src/ui/webmcp/{tools,workflowTools,schemas,register}.js`와 `src/app/webmcpHost.js`의 등록·입력·세션 계약을 고정한다. 모듈별 업무 동작과 기존/신규 tool·schema의 대응표를 만들고 입력/조회/실행/취소/내보내기 결손을 각 milestone에 배정한다.

**수정 책임:** `verification/specs/phase24/`, `tests/fixtures/p24/`, `tools/run-phase24-tests.mjs` 제안; 실행 기록은 이 문서 묶음에 추가.

**집중 시험:** T00. 첫 RED는 구현 전 결함 또는 미지원 동작을 의미 있게 재현해야 한다. import 실패만으로 수치 결함을 재현했다고 기록하지 않는다.

**개발 완료:** 지원 범위·필수검토 목록·첫 기준 예제·시험 선택 정책이 고정되고 D01~D12의 담당 milestone과 미결 조건이 연결됨. 역사적 PASS를 새 검증으로 복사하지 않음.

## M1 — 재료·단면·실제 상세의 공통 입력

**진입:** M0의 범위·단위·규칙 참조 구조 확정.

1. `materialSchema`를 해석 물성, 설계값, 제품/환경 조건, 출처로 나눈다. concrete/steel/timber/masonry를 명시하고 모호한 입력을 steel로 추정하지 않는다. 목재 방향별 값, 조적체/유닛/모르타르/그라우트 구분을 저장하며 미지원 계산 경로는 capability로 차단한다.
2. 콘크리트와 철근 재료를 분리 참조한다. 강재는 두께별 강도/제품, 목재는 등급·제품·함수율·사용환경, 조적은 보강 여부·벽체 역할·필요 강도 등의 필수 조건을 재료별로 검증한다. 실제 규칙이 없는 재료에는 가상의 강도 검토를 생성하지 않는다.
3. 단면 치수·국부축·단위와 A/I/J의 관계를 검증한다. 형상 변경 시 파생값을 재생성하고 수동 override는 출처·유효 범위를 갖도록 한다. 등방성 E/G/nu 조건과 목재 방향성을 구분한다. 범위를 벗어난 값·순환 참조·음수/비유한 값은 명시적으로 거부한다.
4. 제공 배근을 구간·층·위치·철근 재료·직경/개수/간격/다리 수·피복으로 저장한다. 정착·이음·후크와 사용자 고정 영역을 표현할 자리를 만든다. 철근 면적 직접 입력과 실제 배근이 충돌하면 우선순위를 숨기지 않고 오류/명시적 모드로 처리한다.
5. 접합부는 연결 부재와 위치·좌표계·형식·해석 강성 가정, 기초는 지점·형식·실제 치수·배근·지반 출처를 가진 객체로 저장한다. 계산식 구현은 M6/M7에서 진행한다.
6. 기존 라이브러리·설계입력 UI와 WebMCP/명령 브리지에 같은 검증·preview/apply 계약을 연결한다. 조회·폼 열기·미리보기는 모델을 바꾸지 않는다. 단위 변환은 공통 경계에서 한 번 수행한다.

**주요 코드:** `src/materials/{materialSchema,sectionSchema,registry,libraryEdit}.js`, `src/modeling/designInputCommands.js`, `src/ui/{phase7LibraryWorkflow,indexSectionLibraryPanel,indexDesignReview}.js`, 실제 해당 명령을 노출하는 bridge/WebMCP schema. 새 세부 schema는 `src/modeling/designInputs/` 제안.

**집중 시험:** T01~T03. 유효 입력 1개씩과 누락/단위 오류/충돌 경계, UI/API 동일 오류, 조회 불변성.

**개발 완료:** 네 재료의 입력을 손실 없이 읽고 변경할 수 있고, 해석 가능·설계 가능·상세 생성 가능을 구분함. 실제 상세가 없는 기존 철근비 모델은 `assumed` 상태로 유지됨.

## M2 — 변경 영향·결과 identity·저장 호환

**진입:** M1의 입력 객체와 참조 버전 고정.

1. 현재 `p19-input-v1`을 그대로 보존하고 새 버전의 해석/설계/상세/출력 종속 identity를 도입한다. 검증되지 않은 키 제외로 재사용 범위를 넓히지 않는다. 해석에 사용한 정규화된 입력·resolved 물성·solver 설정·조합·수치 모듈 버전을 바인딩한다.
2. 배근 변경이 적용 강성·질량에 영향이 없는 경우에만 설계 재검토로 한정한다. 단면·밀도·E·균열강성·접합강성·지반 스프링·구속 변경은 관련 해석부터 재실행한다. 영향 판정 불가 시 재해석한다.
3. preview는 예상 재실행 단계와 변경 diff를 반환하고 apply는 base revision 검증 후 한 transaction으로 커밋한다. 자동 후보에도 같은 경로를 사용한다. 여러 명령이 겹치면 오래된 적용을 거부한다.
4. native 저장·product-book·자동저장·IndexedDB checkpoint·undo/redo·복원에서 새 객체/참조/hash가 보존되게 한다. 중단·변조·누락된 상세는 완전 복원으로 표시하지 않는다.
5. 이전 결과는 이전 identity 계약으로 조회 가능하게 보존한다. 새 규칙으로 자동 재해석한 것처럼 재결속하지 않는다. 완전한 원본으로 동등성을 입증하는 migration이 없으면 재실행을 요구한다. 구버전 내보내기에서 새 필드를 조용히 버리지 않는다.

**주요 코드:** `src/core/workflowIdentity.js`, migration 관련 코드, `src/compute/product/workflowResults.js`, `src/ui/{indexNativePersistence,indexImportAgentState,indexAgentCommandBridge}.js`, 제품 checkpoint/store.

**집중 시험:** T04~T05. 동일 해석 입력의 설계 변경 재사용, 물성/단면/구속 변경 무효화, stale apply 거부, 작은 저장/복원·중단 fixture.

**개발 완료:** 무엇을 재사용하고 무엇을 다시 계산하는지 결과마다 근거가 남음. 과거 파일이 새 기본값으로 덮이지 않고, UI/WebMCP/저장 상태가 같은 revision을 가리킴.

## M3 — 공통 설계 계산과 검토 상태

**진입:** M2의 종속 identity와 원자적 결과 등록 사용 가능.

1. `finalizeElasticAnalysis`와 `elasticReviewService.calculateReview`의 `runDesignChecks` 호출을 공통 검토 서비스로 모은다. 계산 소유자는 `src/design/evaluation/` 제안; 제품 서비스는 조정·등록을 맡는다. solver 안으로 UI/보고서 의존성을 넣지 않는다.
2. 조합·국부축·위치·부호·결과 집합을 보존한 동시 작용력 묶음으로 검토한다. 축력과 양축 모멘트, 접합부의 연결 부재 작용력, 기초 N/V/M을 독립 최대값으로 조합하지 않는다. 단순 포락 표와 지배 검토 요약은 공통 검사 결과의 다른 view로 만든다.
3. `steel.js`가 모든 재료 검토의 실질 진입점인 구조를 공통 router로 정리한다. 현재 steel/concrete 호환 adapter를 두고 timber/masonry 미구현 규칙에는 이유를 반환한다.
4. 부재/접합/기초 유형별 필수검토 목록을 먼저 생성하고 각 결과를 채운다. 입력 누락, 규칙 미지원, 아직 연결 안 됨, 낡은 결과, 계산 실패를 구분한다. `N_A`에는 규칙의 적용 제외 근거가 필요하다.
5. 과거 NG76의 범주·고유 대상·조합별 행 수를 분리 표시한다. 임의 250kN 접합 지표는 예비 진단으로 보존하고 최종 RC 접합 합격/불합격을 대신하지 않게 한다. 표시에서 빠진 정착/구속 등의 필수검토도 누락으로 집계한다.
6. 보고서·조회는 등록된 평가 snapshot을 읽는다. 같은 입력/수요/규칙 key의 동일 평가를 재사용하되 선택 조합이 다르면 다른 검사 집합을 만들고, 입력 수정 없이도 rule pack 변경 시 결과를 무효화한다.

**주요 코드:** `src/compute/product/{elasticAnalysisWorkflow,elasticReviewService,workflowResults}.js`, `src/design/{steel,concrete,connectionFoundation}.js`, demand package·summary 관련 코드.

**집중 시험:** T06~T07. 두 조합의 지배 위치가 엇갈리는 작은 수요, UI/보고서 동일 판정, 필수검토 행 생성과 중복 없는 집계.

**개발 완료:** 수치 계산이 한 서비스에 있고 선택/요약/조회에서 같은 검사 ID·수요·판정이 유지됨. 미검토 행 제거 또는 예비 지표 이름 변경으로 합격을 만들지 않음.

## M4 — RC 제공 배근 내력·상세·사용성

**진입:** M1 상세 계약, M3 동시 수요·규칙/검사 계약. 구현할 각 규칙의 판본·적용 범위와 독립 기대값을 먼저 고정.

1. `selectStirrups`에서 최소 간격으로 잘린 뒤 제공 Av/s가 부족한 후보를 `INSUFFICIENT_REINFORCEMENT`로 판정한다. 상세 trace의 `status || 'OK'` 경로를 제거한다. 후보 없음과 계산 실패를 구분한다.
2. 실제 제공 스터럽의 기여를 포함한 전단 검토를 구현하고 최소 배근·간격·강도 상한·적용 조건을 별도 검사한다. 주근/스터럽 변경으로 유효깊이가 바뀌면 실제 위치에서 다시 산정한다. 필요 철근량, 제공량, 사용된 내력 성분을 같은 trace에 남긴다.
3. 보의 양방향/부호별 휨과 기둥의 축력-2축휨을 실제 철근 위치·강도·단면으로 계산한다. 현재 철근비·0.9d·단순 interaction 예비식을 검증된 상세 계산으로 자동 승격하지 않는다. 단면 평형/변형 적합과 수렴 조건을 정의하고 축·부호를 일관되게 사용한다.
4. RC 구간별 최소/최대 배근, 순간격·피복·층수, 띠철근/스터럽, 정착·이음·구속 규칙을 구현한다. 이음 위치·개구부·내진 상세 등 첫 범위 밖 조건은 필수검토의 미지원으로 남긴다.
5. 선택한 기준의 사용성 검토를 강도 조합과 구분한다. 균열·즉시/장기 처짐 등에 필요한 지속하중·강성·환경 입력과 지원 해석 방법을 명시한다. 현재 utilization 비례 trace를 실제 처짐 검토로 사용하지 않는다. 입력/방법이 없으면 `NOT_CHECKED`이며 자동 후보의 완료 판정에도 반영한다.
6. 후보 추천기는 위 실제 상세 검토기를 다시 호출한다. 후보의 예측 철근량만으로 PASS 처리하지 않는다. RC 상세/도면에 사용할 canonical reinforcement를 반환한다.

**주요 코드:** `src/design/{concrete,rcDetailing}.js`, `src/design/rc/{beam,column}.js` 및 실제 호출 중인 RC trace, `src/design/evaluation/` 제안. 해당 경로에 필요한 순수 단면 계산만 분리/재사용.

**집중 시험:** T08~T11. 제공량 증가 반응, 전단 상한·간격 경계, 독립 단면 평형·양축/부호, 실제 d 변화, 물리량 기반 사용성, 누락 시 합격 차단.

**개발 완료:** 지원 범위의 RC 강도·필수 상세·사용성 검사를 실제 입력으로 평가함. 미지원 프로젝트를 `RC 설계 완료`로 표시하지 않고 모든 제한을 검사 목록에 남김.

## M5 — 자동 후보·수정 적용·재계산

**진입:** M4 제공 상세 검토가 작은 기준 문제를 통과. M2의 재실행·transaction 계약 사용.

M5 개발 시험의 완료 범위는 RC 부재로 명시한다. 접합/기초 후보는 M6/M7에서 연결하며 그 전까지 프로젝트 전체의 필수검토 미완료 상태를 유지한다. 부재 범위 합격을 전체 구조 설계 완료로 집계하지 않는다.

1. 사용자 제약을 먼저 고정한다: 허용 단면 범위/증분, 철근 제품·직경·다리 수·간격, 배근 층수, 부재 그룹, 수정 금지 영역, 탐색 횟수·시간·메모리 상한. 실제 구매 가격 자료가 없으면 비용 최적화 대신 철근량·단면량 등의 명시적 지표를 사용한다.
2. RC 배근 후보를 먼저 탐색하고 배근만으로 해결되지 않을 때 허용 단면 후보로 확장한다. 재료 강도·지반값·하중·기준·사용자 고정 조건을 임의로 변경하지 않는다. 각 후보는 전체 필수검토를 평가하고 다른 검사 악화도 비교한다.
3. 후보는 격리 snapshot에서 평가한다. 상위 설계 workflow가 원본→후보→평가 run 계보를 관리한다. 각 변경에 새 revision·plan을 발급하고 기존 해석 workflow의 `STALE_INPUT` 보호를 유지한다.
4. 선택 후보를 적용할 때 다시 현재 revision을 확인한다. 허용한 자동 적용 모드에서는 매번 확인창 없이 정해진 한도 내에서 커밋한다. 제안 모드에서는 preview와 평가를 반환한다. 다른 사용자 변경이 끼어들면 자동 덮어쓰기를 하지 않는다.
5. 판정은 필수검토 충족 → 제약 위반 없음 → 명시된 목적함수 순서다. `NO_FEASIBLE_DESIGN`, `NEEDS_INPUT`, `BUDGET_EXHAUSTED`, `UNSUPPORTED`, `SOLVER_FAILED`를 구분하고 실패 후보·이유를 요약 보존한다. 반복 동형 후보는 hash로 제거하고 진전 없는 반복을 중단한다.
6. 후보 계산은 한 번에 하나만 실행한다. 원본/최선 결과·현재 후보 외의 대형 결과를 계속 복제하지 않는다. 취소·오류·시간/메모리 한도에서 임시 버퍼와 Worker/GPU 세션을 해제하고 이미 확정한 원본 상태를 보존한다.

**주요 코드:** `src/compute/product/elasticReviewService.js`의 plan/run 경계, 제안 `src/compute/product/designWorkflowService.js`, `src/design/optimization/`, 기존 model command/undo/result store.

**집중 시험:** T12~T13. 배근만 변경, 단면 변경으로 재해석, 해 없음, 예산 종료, stale apply, 취소/오류 rollback을 작은 후보 2~3개로 검사.

**개발 완료:** 작은 RC 예제에서 부족 원인→후보→실제 검토→선택 적용→필요 재계산→전후 비교가 연결됨. 합격 가능한 후보가 없을 때 설정을 완화해 합격시키지 않음.

## M6 — RC 접합부·정착의 실제 연결

**진입:** M3 공통 검사와 M4 실제 배근, M5 반복 제어기 사용 가능.

1. RC 보-기둥 접합부와 기둥-기초 정착의 실제 연결 객체를 탄성모델 절점/부재단에 연결한다. M0에서 등록한 직교·내부/외부 등 형식에만 규칙을 적용한다. 연결 누락·잘못된 참조·방향은 사전 검사한다.
2. 같은 조합의 연결 부재 단부력을 접합 좌표계로 변환하고 부재단/절점 위치 차이·편심·평형을 처리한다. 요구되는 정착력 등 설계 수요의 출처를 기록한다. 기존 합성 최대값 지표를 실제 수요로 쓰지 않는다.
3. 접합부 전단·정착/이음·구속·철근 배치와 해당 구조계의 필수 조건을 검사한다. 지원되지 않는 내진 조건이나 상세는 미검토다. 부재 배근 변경이 접합 수요·정착/혼잡에 미치는 영향을 다시 평가한다.
4. 배근·구속·허용 치수 후보를 M5에 등록한다. 접합/부재 강성이나 오프셋이 바뀌면 M2 규칙으로 재해석한다. 상세와 해석의 핀/강접 가정이 불일치하면 자동 완료를 막는다.
5. 철골/목재/조적 객체에는 같은 참조·입력 검증을 제공하되 전용 규칙 미구현을 표시한다. 예비 bolt/weld/basePlate 함수를 RC에 적용하거나 토사 지지력을 주각 콘크리트 지압으로 사용하지 않는다.

**주요 코드:** `src/design/connectionFoundation.js`, `src/design/connection/{detailedReport,basePlate}.js`의 routing 경계, 제안 `src/design/connection/rcJoint.js`, `rcAnchorage.js`, 공통 입력/evaluation/candidate 서비스.

**집중 시험:** T14와 M2 변경 영향 시험 중 접합 강성 1건. 동시 수요·좌표변환·접합 평형, 정착길이/배치 경계, 재료 오분류 차단.

**개발 완료:** 지원 RC 접합부를 실제 객체와 상세로 검토하고 후보를 재평가함. 접합부의 필수검토가 빠진 부재군을 완성 설계로 요약하지 않음.

## M7 — 실제 독립기초 설계·후보

**진입:** M1 기초/지반 입력, M3 동시 반력, M4 RC 규칙, M5 후보 제어기, M6 기둥 정착 사용 가능.

1. 프로젝트에서 채택한 기초 형식만 검토한다. 지점 고정 조건과 실제 기초 객체를 구분하고, 기초 없는 지점은 `MISSING_FOUNDATION_GEOMETRY`로 표시한다. 기존 모든 형식의 예비안을 한꺼번에 최종 설계로 생성하지 않는다.
2. 실제 폭·길이·두께·기둥 위치·피복·철근과 지반값/근거·지하수·마찰/침하 조건을 연결한다. 지지력 값의 순/총(net/gross) 정의, 서비스/강도 조합, 부력·기초/상부 토사 자중의 포함 위치를 명시해 중복 가산을 막는다.
3. 동일 조합의 N/V/M으로 중심·편심 접지압과 접촉 상태를 계산한다. 인장을 전달하지 않는 지반의 부분 접촉/들림을 지원 범위로 정의하고, 지원 외 상태를 단순 q=N/A로 덮지 않는다. 활동·전도와 접지압 한계를 구분한다.
4. 실제 단면/배근에서 휨·일방향 전단·펀칭·기둥 정착을 평가한다. `footing.js`의 고정 유효깊이와 `required-bearing-area`의 무조건 NOT_CHECKED 경로를 제거하고 공통 결과로 대체한다. 필요한 침하 검토의 자료가 없으면 누락으로 남긴다.
5. 기초 치수·두께·배근 후보를 M5에 연결한다. 기존 fixed 지지를 유지하는 치수 변경은 하중/강성 종속성을 확인해 재검토하고, 스프링·경계조건/구조 강성이 바뀌면 재해석한다. 지반 입력을 자동으로 올려 합격시키지 않는다.

**주요 코드:** `src/design/foundation/{footing,detailedReport}.js`, `src/design/connectionFoundation.js`, `src/compute/product/elasticReviewService.js`, 공통 기초 입력/수요/evaluation/candidate 서비스.

**집중 시험:** T15. 중심압축의 독립 q=N/A, 편심·접촉 경계, 실제 두께/d·배근 반응, 조합/자중 중복 방지, 지반 누락·인발·지원 외 형식.

**개발 완료:** 실제 기초 면적·치수 입력이 검토에 반영됨. 기초6곳×조합20개 같은 행 수 자체가 아니라 필수 검사·누락 사유로 상태를 설명함.

## M8 — 배근 객체 기반 도면·수량·계산서

**진입:** M4/M6/M7의 상세 객체와 검토 결과, M2의 버전 관계 확정.

1. RC 보 입면/단면, 기둥 일람/단면, 접합부 및 기초 평면/단면의 도면 모델을 만든다. 철근 중심선·구간·마크·직경·피복·후크·정착/이음이 같은 원본 상세에서 나온다. 지원 밖 벽/슬래브 도면을 임의 생성하지 않는다.
2. 같은 상세에서 철근 수량·가공표·절단 길이를 생성한다. 굽힘 반경·길이 산정 규칙의 판본·가공 가정을 기록하며 입력 없는 부분을 확정 수량에 합산하지 않는다.
3. SVG와 검색 가능한 텍스트를 포함한 벡터 PDF를 제공한다. 기존 Phase22 raster 예비 PDF 경로와 별도 capability로 구분하고, 동일 report snapshot·선택 상세를 사용한다. 렌더러에서 부재 내력이나 필요 철근량을 다시 계산하지 않는다.
4. 부재 ID·상세 revision·해석 run·규칙 버전·검토 범위·미완료 이유를 도면/계산서 manifest에 연결한다. 유효하지 않은 상세는 검토용 표시를 유지한다. 미검토/설계 전이 차단을 숨긴 최종 출력 모드를 제공하지 않는다.
5. 페이지 단위로 렌더링하고 중간 canvas/blob/font/URL 자원을 해제한다. 출력 중 입력 변경 시 혼합 revision의 파일을 만들지 않는다. 고정 snapshot에서 완료하거나 현재성 상실을 명시하는 정책을 통일한다.

**주요 코드:** 기존 report snapshot/artifact 및 Phase22 PDF adapter, 제안 `src/design/detailing/`, `src/reports/drawings/`, 공통 결과 store와 UI 출력 동작.

**집중 시험:** T16. 철근 마크·치수/길이·수량의 독립 기대값, 상세 변경 후 출력 무효화, 최소 1~2쪽의 겹침/한글/잘림 시각 확인·PDF 텍스트 확인. 매 개발 반복에 전체 도면집을 렌더링하지 않는다.

**개발 완료:** 지원 상세의 도면·수량표·계산서가 같은 revision을 참조함. 예비 PDF·배근 일람표·시공용 확정 도면의 기능 상태가 명확함.

## M9 — UI·WebMCP 통합과 종합검증 인계

**진입:** M0~M8의 필수 집중 시험 통과, 미지원/미검증 목록 유지.

1. 기존 설계 화면에서 재료/상세 입력→원인별 검토→후보 비교→자동/선택 적용→재계산→도면/계산서로 이동한다. 각 단계에 현재 revision·남은 작업·중단/되돌리기를 제공한다. 사용자 화면의 문구는 내부 모듈명 대신 설계 행위와 원인을 설명한다.
2. WebMCP는 같은 제품 서비스의 capability/query/preview/apply/plan/run/cancel/export를 호출한다. 도구명·schema 변경은 버전/호환 계약으로 관리하며 같은 요청 key의 중복 apply/run으로 모델이 두 번 수정되지 않게 한다.
3. 1층 작은 합성 RC 골조와 최소 조합으로 기존 CPU 탄성/Direct→검토→후보→재검토→도면/저장까지 한 번 연결한다. 재료 종류별 입력/미지원 경계는 별도 작은 fixture로 확인한다. Phase23 GPU 결과의 최종 설계 전이 차단도 유지하는지 검사한다.
4. 구현 커밋·대상 파일·테스트 ID·명령/시간/결과·미검증 목록을 manifest로 묶는다. README/기능표는 실제 구현·집중 검증 상태까지만 갱신한다. 공개 산출물에는 합성 입력과 재현 방법만 기본 포함하고 기존 현장/사유 자료를 무차별로 패키징하지 않는다.
5. [후속 종합검증 Q](TDD_VALIDATION_PLAN.md)의 실행 목록을 최종 후보에 고정한다. 종합검증을 이번 단계에서 돌리지 않는다. 이후 결함 수정 시 해당 집중 시험을 먼저 돌리고 Q에서 재검증할 영향 범위를 갱신한다.

**주요 코드:** `src/ui/indexDesignReview.js` 및 실제 관련 input/report panel, bridge/WebMCP 등록부, 공통 workflow/result/persistence 서비스, 기능 metadata·사용자 문서.

**집중 시험:** T17 및 직접 영향 계약 시험. 작은 합성 흐름 1건과 실제 브라우저 대표 화면 확인만 수행한다. 실제 건물·전체 suite·성능 장시간 시험은 Q에 남긴다.

**개발 완료:** `IMPLEMENTED / FOCUSED_VERIFIED / COMPREHENSIVE_PENDING`의 근거와 인계 자료가 존재함. `productionQualified`나 최종 설계 전이를 시험 개수·NG=0만으로 승격하지 않음.

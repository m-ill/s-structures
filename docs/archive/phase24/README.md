> 2026-09-11 재계획: Phase24는 부분 구현 기준선으로 보존하고 미완료 범위를 [Phase25](../../phase25/README.md)로 이관했다. 아래 계획/실적은 당시 기록이며 전체 마일스톤 완료가 아니다. 현재 잔여 작업의 정본은 [32건 재점검 대장](../../phase25/GAP_AUDIT.md)이다.


2026-09-11 · 계획 v1 · **부분 구현 기준선 / 잔여 Phase25 이관 / 전체 완료 아님**

이 문서는 재료·단면·배근·접합부·기초를 **기존 탄성설계 과정 안에 통합**하는 다음 개발 페이즈의 정본이다. 사용자의 요청에 따라 TDD로 구현하되 개발 중에는 변경 범위의 작은 시험만 수행한다. 전체 회귀와 종합검증은 다음 별도 실행에서 수행한다.

## 목표와 사용자 흐름

사용자는 재료별 물성·크기·실제 상세와 설계 제약을 입력한다. 프로그램은 기존 탄성/Direct 해석 결과로 부재·접합부·기초를 검토하고, 부족하거나 입력이 빠진 이유를 구분한다. 허용 범위에서 배근·단면·기초 치수 후보를 만들고, 필요한 단계부터 다시 계산하여 선택된 상세의 도면·수량표·계산서를 생성한다.

`설계 기준·제약 → 재료/단면/상세 입력 → 해석 준비·탄성/Direct → 공통 설계 검토 → 수정 후보 → 변경 영향 판정 → 재해석 또는 재검토 → 상세 확정 → 도면·계산서`

완료 목표는 NG 숫자 감소가 아니다. 정해진 지원 범위에서 실제 제공 상세를 검토하고, 해당 부재·접합부·기초에 필요한 검사 누락 없이 결과와 출력의 버전이 일치하는 것이다. 실제로 불가능한 설계는 원인과 제약을 반환한다.

**모든 업무 모듈의 WebMCP 제어가 필수다.** 입력·조회·실행·취소·후보 적용·결과·내보내기를 공통 제품 서비스로 노출한다. UI와 WebMCP가 같은 계약을 사용하고 각 milestone에서 함께 구현·시험한다. 제어 범위와 기존 도구 확장은 [WEBMCP_CONTROL_CONTRACT.md](WEBMCP_CONTROL_CONTRACT.md)에 정의한다.

## TDD와 검증 정책

1. 작은 실패 시험을 먼저 실행해 원인을 확인한다. 결함을 고치는 최소 구현을 넣고 같은 시험을 통과시킨 다음 구조를 정리한다.
2. 변경 기능 시험과 직접 인접 계약 시험만 실행한다. 기본 개발 경로에서 `npm test`, 전체 phase runner, 21개 비교, 실제 건물, 장시간 메모리·GPU 시험을 호출하지 않는다.
3. 개발 시험은 규칙 1건·부재 1개·접합부 1개·기초 1개 중심이다. 수치 기대값은 고정한 기준/독립 계산에서 먼저 작성한다. 산출물 snapshot만 맞추는 검사는 수치 검증을 대신하지 않는다.
4. 변경 시험의 실패를 나중 종합검증으로 미루고 구현 완료 처리하지 않는다. 긴 환경·전 범위 시험은 별도 대기표에 범위와 이유를 남긴다.
5. M9 완료 시 상태는 **구현 완료·집중 검증 완료·종합검증 대기**다. 출시/최종 설계 자격은 다음 종합검증 결과와 독립 검토에 따라 별도 판정한다.

구체적인 시험 ID, 기대 동작, 실행 예산, 증거 구조와 후속 종합검증 목록은 [TDD_VALIDATION_PLAN.md](TDD_VALIDATION_PLAN.md)에 정의한다. 이번 문서 작성 자체는 TDD 구현이나 수치 PASS로 집계하지 않는다.

## 재료·단면 입력 계약

해석 물성, 설계 강도, 실제 상세를 구분해 저장하되 동일한 부재·재료 버전으로 연결한다. 재료별 폼은 공통 schema에서 UI와 WebMCP에 함께 제공한다.

| 재료 | 추가할 입력 묶음 |
| --- | --- |
| 공통 | 명시적 재료 종류, 규격·판본·제품·출처, E/G/nu/밀도·단위, 적용 범위, 시험값/규격값/가정값 구분, 단면 형상·치수·로컬축 |
| RC | 콘크리트 강도와 철근 강도를 별도 재료 참조로 관리; 주근·스터럽·띠철근의 직경·개수·간격·층·위치; 피복·정착·이음; 설계에 필요한 강성 가정 |
| 철골 | 강종·판두께별 강도, 압연/용접 형상, 부재별 좌굴·횡지지 조건, 볼트·용접·판 재료와 실제 치수 |
| 목재 | 수종·등급·제품(제재목/집성재 등), 방향별 강도·강성, 함수율·사용환경·하중지속 조건, 실치수·노치·구멍, 접합재 정보 |
| 조적 | 내력벽/비내력벽 및 보강/무보강 구분, 조적체 강도, 유닛·모르타르·그라우트, 벽 두께·유효 면적·개구부, 보강근·정착·지지 조건 |

치수 변경 때 A/I/J 등의 파생 성능을 다시 산정하고 불일치한 수동 값은 명시적으로 처리한다. E/G/nu 일관성 규칙은 등방성 재료에 적용하고 목재 방향성을 같은 규칙에 억지로 맞추지 않는다. 미확인 재료는 강재로 자동 추정하지 않고 설계 지원 여부를 표시한다. 기존 프로젝트 물성값을 새 기본값으로 덮어쓰지 않는다.

## 자동 RC 설계와 배근도

필요 철근량 → 사용 가능한 직경·개수·간격 후보 → 제공 배근으로 재검토 → 구간별 상세 확정 → 도면 생성의 순서로 연결한다. 후보는 강도뿐 아니라 최소/최대 배근, 층수·순간격, 정착·이음, 구속·내진 상세와 시공 가능 조건을 함께 평가한다. 허용 단면 상한·층고·철근 규격·사용자 고정 상세는 탐색 제약으로 보존한다.

현재 RC 전단은 제공 스터럽 기여가 없으므로 먼저 보강해야 한다. selectStirrups의 간격 하한 적용 후 부족 판정 누락도 자동 선택 전에 수정한다. 실제 배근이 확정되기 전까지 가정 철근비를 사용한 OK는 최종 배근 합격으로 바꾸지 않는다.

도면 원본은 문자열 일람표가 아니라 검증된 배근 객체다. 부재/철근 마크, 철근 중심선·구간, 지름·개수·다리 수·간격, 피복, 굽힘·정착·이음 위치를 저장한다. 이 원본에서 보 입면/단면, 기둥 일람표/단면, 슬래브 배근 평면, 기초 평면/단면, 철근 가공표를 생성한다. SVG/PDF 벡터 출력부터 구현하고 DXF 출력으로 확장한다. 기존 DXF 가져오기는 도면 출력 기능이 아니다. 현재 예비 검토 PDF도 시공 배근도와 별개다.

치수·철근 번호·수량·절단 길이와 계산서의 일치 여부를 검증하고, 미검토 상세는 도면에서도 상태가 유지돼야 한다. 배근 객체가 바뀌면 관련 도면·계산서를 함께 갱신한다.

## 접합부의 실무 객체화

부재를 골랐을 때 접합부를 생성하고 실제 연결되는 부재·면·위치·전달력·강성 가정·상세를 갖도록 한다.

- RC: 보-기둥 접합부, 기둥-기초 정착, 벽-슬래브 연결 등과 필요한 전단·정착·구속 상세.
- 철골: 단순전단·모멘트·가새·이음·주각 유형별 판/볼트/용접/앵커 배치와 해당 한계상태.
- 목재: 못·나사·볼트·철물의 배치, 섬유방향·단부/연단 거리·인발/전단·쪼개짐 검토.
- 조적: 벽체 연결, 바닥/지붕 정착, 개구부 주변과 보강 상세.

하중조합과 같은 위치에서 동시에 발생하는 작용력을 전달한다. 서로 다른 위치의 최대값을 합친 현재 예비 지표는 실제 접합 설계의 원본 수요로 쓰지 않는다. 접합 상세가 핀/강접/반강접 해석 가정과 다르면 재해석 또는 불일치 처리가 필요하다.

기존 상세 함수도 검증이 필요하다. 예를 들어 basePlate.js는 foundationRow의 allowableBearing/requiredArea를 재사용한다. 토사 지지력과 주각의 콘크리트 지압·강판 휨·앵커 정착 검토를 분리해야 한다. 파일명이나 formulaId에 KDS가 있다고 해당 설계 기준 전체를 구현한 것은 아니다.

## 기초의 실무 객체화

해석의 fixed 지점은 변위 경계조건이며 실제 기초 치수·배근을 정의하지 않는다. 현재 상세 report는 모든 지점의 독립기초·말뚝 및 전체 복합/매트 예비안을 생성하지만 프로젝트에서 채택한 기초 유형을 확정하고 재검토하는 연결이 없다.

지반값·지하수·허용침하 등 근거 입력과 각 기초의 형식·평면·두께·기둥/벽 위치·배근을 저장한다. 조합별 N/V/M과 서비스/강도 검토 구분, 자중 포함 규칙을 명시한다. 실제 치수로 접지압·편심·들림·활동·휨·전단·펀칭을 검토하고, 기초 형식에 맞는 지반·침하/말뚝 검토를 수행한다.

현재 footing.js의 추천 두께와 배근 계산에 쓰는 고정 유효깊이 등도 실제 상세와 일치하도록 고쳐야 한다. 구조 형식·지반 입력이 없을 때 자동 탐색은 필요한 입력과 조건부 예비안을 반환하며, 근거값을 임의 조정해 합격시키지 않는다.

## 통합 실행 흐름

프로젝트 설계 기준/규모/제약 → 재료·단면/하중 → 구조 해석 → 부재·접합부·기초 설계 → 수정 후보 → 필요한 재해석·재검토 → 상세 도면·수량·계산서.

모든 단계는 동일한 모델/재료/하중/배근/규칙 버전을 참조한다. 철근만 바뀌고 현재 해석 강성에 영향이 없다면 설계만 다시 검토할 수 있다. 단면·자중·균열강성·접합강성·기초 지지조건이 바뀌면 관련 구조 해석도 다시 수행한다. 최신 결과가 없는 경우 이전 도면을 현재 승인된 출력처럼 표시하지 않는다.

에이전트는 규칙 기반 계산기를 호출해 변경 후보와 전후 결과를 만든다. 재료 강도·설계 기준·지반값을 근거 없이 변경하지 않는다. 단면/철근/연결 상세 선택은 사용자가 정한 범위 안에서 자동화한다. 원인 설명·변경 이력·중단 사유·되돌리기를 남긴다. 합격은 NG 수만이 아니라 적용해야 하는 검토 목록과 결과의 충족 여부로 판정한다.

## 기존 탄성설계 흐름의 수정 위치

사용자 보완 의견: 이 기능들은 기존 탄성설계 과정 안에 들어가야 한다. 별도 계산 도구를 추가하는 계획으로 이해되지 않도록 통합 위치를 명시한다. 기존 해석·설계·저장·보고서 흐름 자체의 수정이 필요하다.

| 기존 단계 / 코드 | 삽입하거나 변경할 책임 |
| --- | --- |
| 재료 라이브러리·designInputCommands | 재료별 물성·단면·제공 배근·접합부·기초 입력. UI/WebMCP 공통 계약과 변경 preview |
| prepareElasticAnalysis / canonical domain | 해석에 쓰이는 물성·강성·축·지지조건 확인. 설계 지원 부족과 해석 불가능을 구분 |
| CPU/GPU 조합 해석·Direct | 기존 검증된 solver를 사용하되 변경된 단면·강성·연결·지지조건을 반영 |
| finalizeElasticAnalysis / elasticReviewService.calculateReview | 공유 설계 검토 서비스로 조합별 동시 작용력·제공 상세를 검토하고 동일 판정에서 요약과 상세를 생성 |
| elasticReviewService.planWorkflow/runWorkflow | 해석 실행 후 부재/접합/기초 검토, 보완 후보, 변경 적용, 재해석/재검토 분기를 조정 |
| workflowIdentity / workflowResults | 해석 입력·설계 상세·도면 버전의 변경 영향을 명시하고 저장/복원/낡은 결과 판정을 함께 개정 |
| indexDesignReview / WebMCP / 보고서·도면 | 같은 workflow 상태에서 누락 입력·NG 원인·후보·변경 전후·상세도·계산서를 제공 |

현재 finalizeElasticAnalysis와 calculateReview가 모두 runDesignChecks를 호출한다. 전자는 주로 envelope 요약, 후자는 선택 조합별 상세이므로 단순히 결과 하나를 복사하면 안 된다. 공통 조합별 검토 계약과 계산 소유자를 두고 각 화면은 그 결과를 필요한 형태로 요약해야 한다. 특히 축력·2축 모멘트·접합 수요는 같은 조합/위치의 동시 작용력을 보존한다. 보고서 렌더러가 별도의 설계 계산을 수행하지 않는다.

현재 runWorkflow는 미리 정한 해석 케이스를 순서대로 실행하고 입력이 바뀌면 STALE_INPUT으로 중단한다. 자동 보완에서 이 보호를 해제하지 않는다. 각 변경 후보에 새 입력 버전과 새 계획을 발급하고, 상위 설계 workflow가 원본→후보→재검토 관계를 관리하도록 확장한다.

현재 workflowIdentity는 설계 상세를 포함한 모델 전체를 hash하므로 배근만 바꿔도 기존 해석 결과가 stale이 된다. 설계만 재검토하려면 실제 해석 종속 입력이 같다는 명시적 새 버전 계약이 필요하다. 계약이 없거나 영향이 불명확하면 재해석한다. 이전 hash 규칙과 저장 기록은 바꾸지 않고 새 버전을 도입한다.

재실행 분기: 제공 철근 변경이 적용한 해석 강성·질량에 영향을 주지 않는다면 설계/상세/도면만 재검토한다. 단면·E·밀도·균열강성·접합강성·기초 지지조건 변경은 영향을 받는 해석 케이스부터 다시 실행한다. 글꼴·표현 수정은 도면/보고서만 갱신한다. 후보는 순차 처리하고 작업 버퍼와 결과 보존량에 상한을 둔다.

## 개발 순서 제안

1. 재료 종류·단위·입력 schema와 상태/필수검토 목록을 공통화한다. 네 재료의 구조는 먼저 설계하되 미구현 설계는 명시한다.
2. RC 보·기둥의 제공 배근 내력과 후보 생성·변경·재검토를 완성한다.
3. RC 접합부·독립기초를 연결해 골조부터 기초까지 하나의 설계 흐름을 완성한다.
4. 동일한 검증 상세에서 배근도·수량표·계산서를 생성한다.
5. 철골 부재·접합·주각 설계와 상세도를 같은 구조에 연결한다.
6. 목재·조적은 전용 물성·기준·해석 적용 범위·접합 규칙으로 확장한다.

개발 중에는 작은 부재/접합/기초 기준문제와 영향 범위의 집중 검사만 사용한다. 자동 후보에 대한 합격 검사를 생략하지 않는다. 도면은 시각 확인과 치수·수량·참조 무결성 검사로 검증한다. 실제 건물 재시험과 긴 전체 회귀는 이번 조사에서 수행하지 않았다.

## 기준 자료와 적용 방식

국내 프로젝트는 적용 KDS 및 관련 제품 규격의 판본·조항을 프로젝트에서 확정해 규칙 모듈에 연결한다. 외국 기준은 모듈 구성·검증 범위 참고로 구분하며 서로 다른 기준의 계수나 합격 조건을 섞지 않는다.

- [ACI 구조콘크리트 기준 범위](https://www.concrete.org/publications/concreteresourcesubscriptions/collectiononline/collectionsearch.aspx?MCP_DocID=4377&m=abstract): 재료·강도·사용성·상세·정착/이음·문서 정보가 연결되는 범위 참고.
- [AISC 360](https://www.aisc.org/aisc/publications/current-standards/aisc-360/)와 [AISC 303-22](https://www.aisc.org/globalassets/aisc/publications/standards/a303-22w.pdf): 강구조 및 실제 접합 설계/제작 상세 정보의 범위 참고.
- [USDA Wood Handbook 2021](https://research.fs.usda.gov/treesearch/62200)과 [목재 기계적 특성](https://research.fs.usda.gov/download/treesearch/7149.pdf): 방향성·수종·등급·사용환경·접합 정보의 분리 필요성 참고.
- [AWC 2024 NDS Supplement](https://awc.org/resources/2024-nds-supplement/): 목재 제품별 설계값 체계 참고.
- [TMS 402/602](https://masonrysociety.org/tms402/): 조적 설계·시공 기준의 독립 범위 참고.
- [KCSC 영문 기준 안내](https://kcsc.re.kr/standardCode/eng): 영문판이 현행 국문판의 최신 개정을 모두 반영하지 않을 수 있으므로 국내 적용 판본 확인에 유의.

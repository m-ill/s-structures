# Phase25 — RC 탄성설계의 KDS 검토·자동 보완 완결


현재 마감 상태는 [2026-09-13 완료 조건 점검표](CLOSURE_AUDIT.md)를 먼저 확인한다. [원문 요구 대조표](REQUIREMENT_AUDIT.json)는 85개 항목의 감사 상태를 보존한다. 아래 초기 문제 목록은 개발 착수 당시의 배경이며 현재 미구현 목록이 아니다.

2026-09-11 · 계획 v1 · **제품 구현 진행 중 / 전체 완료 전**

Phase24에서 만들었지만 완료 조건을 채우지 못한 작업을 이 페이즈로 인수한다. Phase24는 **부분 구현 기준선·잔여 이관**으로 기록하며 M0~M9 전체 완료로 표시하지 않는다. 기존 코드를 폐기하거나 다시 작성하는 계획이 아니다. 실제 구현과 남은 검사를 연결하고, 정해진 RC 지원 범위에서 입력→해석→필수 검토→자동 보완→재계산→도면·계산서가 끝까지 이어지게 한다.

초기 재계획 당시에는 제품 코드를 수정하지 않았다. 이후 사용자 지시로 구현을 시작했다. 현재 진행 및 남은 작업은 [구현 기록](IMPLEMENTATION_STATUS.md)을 따른다. Phase24 기준선과 일치하는 구현 관련 파일 767개를 확인했고, solver를 실행하지 않는 작은 합성 수요로 6가지 현상을 조사했다. 이전의 17파일·18실행 통과는 해당 집중 시험의 실적이다. 새로 확인한 결손이나 전체 KDS 적합성의 증거로 확대하지 않는다.

## 이번에 먼저 해결할 문제

1. `rc-code-compliance` 등 필수 항목이 항상 미검토여서 정상적인 완료·자동 적용 경로가 닫혀 있다. 검사를 삭제하지 않고 실제 규칙·적용 제외·누락 집계로 채운다.
2. KDS 원문 해시 일치만으로는 조항 존재·적용 조건·계산 구현의 정확성이 입증되지 않는다. 출처→규칙→입력→수요→계산→판정의 연결을 추가한다.
3. 강도/사용성/장기/예상강도 수요의 종류와 필요한 조합을 먼저 확정해야 한다. 처짐용 전체 사용하중에서 고정하중이 빠지는 경우부터 차단한다.
4. 해석 직후 summary, 별도 탄성 검토, 제공 상세 검토가 같은 canonical 결과와 완료 정의를 사용하게 한다.
5. 남은 RC·접합부·기초 규칙과 상세가 채워진 뒤 자동 반복과 완전한 출력으로 연결한다.

## 지원 범위

기존 Phase24의 비프리스트레스 직사각형 RC 보·띠철근 기둥, 직교 보-기둥 접합 및 기둥-독립기초 정착, 중심·편심 직사각형 RC 독립기초를 인수한다. 기존 CPU 탄성/Direct·강체 다이어프램 결과를 이용한다. 설계 구조시스템, 내진 상세 등급, 콘크리트/철근 등급, 환경, 하중·조합은 명시 입력과 규칙 적용표로 묶는다.

지원표는 `구조시스템 × 대상 형식 × 재료/환경 × 요구 검토 × 수요 종류 × KDS 판본` 단위로 작성한다. 현재 특수모멘트골조 접합 전단 함수 하나를 일반·중간·특수 접합 전체 지원으로 확대하지 않는다. 일반/중간/특수 시스템의 적용 가능성과 필요한 상세를 M0에서 조사하고, 선택된 프로파일의 필수 규칙은 M2~M5에서 구현한다. 첫 프로파일 외 시스템은 명시적인 미지원 항목이며 적용 가능한 것으로 추정하지 않는다.

고강도 중간값, 비틀림, 장기 사용성, 접합 구속·정착, 편심 펀칭 등 원래 미완료였던 항목을 '지원 범위 밖'이라는 문구로 조용히 지우지 않는다. 세부 규칙이 지원 프로파일에 필요하면 필수 작업이다. 원래 범위를 변경하려면 변경 내용·이유·영향과 별도 후속 항목을 기록한다.

지반값·현장 조건·하중·재료 강도는 프로그램이 합격을 만들려고 변경하지 않는다. 지반 보고서 등 외부 입력이 부족하면 필요한 자료와 계산 불가 사유를 반환한다. 설계 후보가 없으면 해 없음, 자료가 없으면 입력 필요, 계산법이 없으면 미지원으로 구분한다.

## 마일스톤

아래는 전체 목표다. 현재 M0~M9는 부분 구현 중이며, M10 전체 구현 마감 조건은 아직 충족하지 않았다. 세부 상태는 구현 기록과 32건 이관 대장을 따른다. 문서 작성이나 기존 시험 통과로 새 마일스톤을 완료 처리하지 않는다.

| 단계 | 산출물 | 닫는 조건 |
| --- | --- | --- |
| M0 | Phase24 인수, 지원 프로파일·KDS/KS 규칙·이관 대장 | 32건의 책임·의존성·시험·범위가 빠짐없이 배정됨 |
| M1 | 공통 완료 판정·조합 적용성·KDS 규칙 추적 | 필수검사 누락, 잘못된 수요/조항, 경로별 다른 summary를 차단 |
| M2 | 실물 재료·배근·구간·피복·구속 입력과 규칙 | 같은 상세가 UI/WebMCP/저장/계산에서 같은 기하와 의미를 가짐 |
| M3 | RC 강도·전단/비틀림·안정·순간/장기 사용성 | 채택 프로파일의 부재 필수검토가 실제 계산 또는 근거 있는 적용 제외로 채워짐 |
| M4 | 부재단 정착·이음·접합 구속·예상강도 수요 | 배근 변경이 접합 수요와 실제 배치 검토로 자동 전파됨 |
| M5 | 기초 하중 회계·KDS 구조 검토·지반 검토 연결 | 자중 중복 없이 중심/편심 기초·정착의 요구 검토와 근거를 반환 |
| M6 | 부재·접합·기초 후보와 적용 후 자동 재계산 | 허용 범위의 작은 예제에서 보완→적용→재해석/재검토→전후 비교가 자동 연결됨 |
| M7 | Worker·취소·메모리·규모 제한 | 중간 취소·실패·한도에서 원본을 보존하고 임시 자원을 회수 |
| M8 | 실제 상세 형상·전수 일람·수량·계산서 | 같은 snapshot의 모든 상세/검사/근거가 페이지 누락 없이 출력됨 |
| M9 | UI/WebMCP 전 업무·저장·호환 경로 | 사용자/에이전트가 같은 결과를 얻고 중단·복원 후 중복 적용하지 않음 |
| M10 | 개발 완료 판정과 종합검증 인계 묶음 | 구현·집중검증 증거와 Q 대기표를 고정; 미완료를 완료로 승격하지 않음 |

순서는 M0→M1→M2→M3→M4→M5→M6→M7→M8→M9→M10이다. 입력·WebMCP·버전·메모리 기본 보호는 각 단계에 포함하며 M7/M9까지 방치하지 않는다. M7은 Worker와 규모 검증의 마감, M9는 전체 사용자 흐름과 호환성의 마감이다.

## 상태와 완료의 의미

서로 다른 세 가지 상태를 한 개의 PASS로 합치지 않는다.

| 상태 | 의미 |
| --- | --- |
| 개발 완료 | 해당 범위의 입력·계산·판정·UI/WebMCP·저장/출력이 실제 연결됨 |
| 집중검증 완료 | 변경 기능의 독립 기대값·경계·오류와 직접 영향 시험이 통과함 |
| 생산 자격 승인 | 고정된 지원 범위/버전이 후속 종합검증과 독립 검토를 마침 |

계산 성공, 조항 적용, 설계안 충족, 마일스톤 완료, 생산 자격은 별개다. `productionQualified`와 최종 설계 전이는 M10 문서 작성이나 NG=0만으로 해제하지 않는다. Phase24의 M9도 원래 개발 인계 단계였으며 종합검증 Q 완료를 뜻하지 않았다.

각 마일스톤은 연결된 이관 항목이 구현·해당 집중 시험·WebMCP·기록을 모두 갖춘 경우만 닫는다. 남은 필수 구현을 '종합검증 대기'로 옮겨 완료 처리하지 않는다. 이미 구현한 동작에 대한 장시간·전 환경 검증만 Q로 이관한다.

## 개발·검증 원칙

- 사용자가 정한 TDD와 최소 검증을 유지한다. 1개 결함/규칙의 RED→최소 수정→GREEN→직접 영향 확인 순서다.
- 매 수정마다 전체 suite나 21개 비교를 돌리지 않는다. 작은 부재/접합/기초와 미리 작성한 독립 계산값을 사용한다.
- 실제 건물 시험은 제외한다. 주소·대지 조사, 기존 상가주택 시험, 외부 CAD 검증을 이번 단계에 넣지 않는다.
- KDS 근거는 모든 계산 결과에 남긴다. KDS를 적용할 수 없는 기하/일반 역학/외부 지반 입력에는 그 사실과 별도 근거를 명시한다. 임의 조항을 채우지 않는다.
- UI와 WebMCP는 같은 제품 서비스를 호출한다. 조회는 기록을 읽고 계산·최적화를 다시 수행하지 않는다.
- 기존 작업 트리·원자료·이전 evidence를 보존한다. 이번 계획은 push·main 병합·Pages 배포를 실행하지 않는다.

## 다음 재료 페이즈와 관계

기존 문서의 'Phase25 철골 / Phase26 목재 / Phase27 조적'은 확정 전 제안이었다. 이번 사용자 지시에 따라 **Phase25는 RC 잔여 완결**로 확정하고, 재료 확장은 `E-STEEL`, `E-TIMBER`, `E-MASONRY` 후속 대장으로 보존한다. 새 번호와 구현 범위는 RC 공통 계약 정리 후 별도 계획에서 정한다. 철골 부재의 기존 예비 검토를 KDS 완전 설계로 표시하지 않으며, 목재·조적 입력 지원을 전용 설계 지원과 혼동하지 않는다.

슬래브/벽체/프리스트레스·특수 단면, 복합/매트/말뚝기초, 새 비선형 설계 매핑, GPU 생산 자격, 일반 CAD 제작 승인은 원래 별도 범위로 유지한다. 실제 건물 업무 대체 검증은 사용자가 다시 요청할 때 별도 수행한다.

# WebMCP 등록 한도와 실무 워크벤치 개선

## 문제와 원인

기존 브라우저 등록은 전체 93개 기능의 설명·스키마를 한 번에 제공했다. 사이트 JSON은 64,132바이트였지만 공개 주소 origin/pageUrl을 포함한 descriptor는 72,037바이트였다. 설치된 내부 브라우저 구현의 기본 65,536바이트 한도를 초과한다. 기존 테스트의 자체 68,000바이트 기준과 실제 연결 조건이 달랐다.

실무 워크벤치는 전체 화면을 덮었고 다른 탭으로 이동해도 닫히지 않았다. 처음 렌더링된 빈 모델 내용을 숨겨진 DOM에 유지했으며, 결과 선택이 바뀌지 않는 모델 입력 변경에서는 갱신이 누락될 수 있었다. 실제 빈 페이지와 오래된 화면을 구분해야 하며, 기본 하중케이스·조합만으로 모델 작성 완료를 표시해서는 안 된다.

## 변경

- 브라우저에는 검색·명세 조회·읽기 호출·쓰기 호출의 고정 4개 도구를 등록한다. 기존 93개 기능의 이름·입력 검증·실행 함수·세션 결속은 유지한다. 전체 기능은 페이지 조회로 탐색 가능하며 read/write 채널을 구분한다.
- 주소 정보를 포함한 등록 크기는 공개 기본 URL에서 2,563바이트다. 24KiB 내부 예산, 긴 프로젝트 URL 및 향후 1,000개 기능 조건을 검사한다. 페이지 내 도구를 반복 재등록하지 않는다.
- 등록 요청과 실제 에이전트 조회·도구 응답 상태를 구분한다. 브라우저 미지원·사용자 비활성·네트워크 차단을 우회하거나 연결 성공으로 표시하지 않는다.
- 데스크톱 워크벤치는 오른쪽 공간을 사용하고 모델 캔버스 공간을 확보한다. 리본 높이에 맞춰 위치를 갱신하고 캔버스를 재측정한다. 좁은 화면에서는 복귀 버튼으로 모델링에 돌아간다.
- 모델링 복귀 버튼·Escape·다른 탭 전환·WebMCP 화면 선택으로 닫는다. 해석이나 자동 설계 실행만으로 창을 열지 않는다.
- 닫힌 창의 본문은 비우고, 열 때 현재 공유 모델에서 다시 만든다. 모델 트랜잭션·Agent 편집·설계 입력 적용 시 열린 창을 갱신한다.
- 빈 모델은 입력 필요 상태로 설명하고 모델링 진입점을 제공한다. 과거 Phase 13 개발 문구는 현재 검토 범위 안내로 교체했다.

## 검증

- `webmcp-browser-catalog`: 전체 기능 탐색, 명세, 읽기/쓰기 차단, 원본 입력 검증, 페이지 세션 폐기, 장래 도구 수 증가.
- `p25-m9-browser-definitions`: 원본 상세 스키마 보존과 긴 URL을 포함한 실제 등록 예산.
- `workbench-model-lifecycle`: 빈 모델→부재 추가의 표시 갱신, 페이지 교체, 3개 다른 탭으로 복귀, Escape, 숨겨진 DOM 정리.
- 기존 WebMCP 실제 솔버 연계 검사와 Phase13 워크벤치 검사를 유지한다. 연결·생명주기 관련 4개 검사를 필수 Pages 배포 검사에 추가했다.
- 실제 내부 브라우저 로컬 탭에서 fetchTools, 목록·명세 조회, get_project_context, set_workspace_view 호출을 확인했다. 8절점·8부재 모델과 워크벤치의 동시 표시, 탭 전환 후 닫힘을 확인했다.

기존 사용자 모델의 원자료 누락이나 구조설계 입력 적합성을 자동 수정했다는 의미는 아니다. 수치 해석식은 변경하지 않았다.

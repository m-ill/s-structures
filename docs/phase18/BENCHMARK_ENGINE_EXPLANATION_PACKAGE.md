# 벤치마크 해석엔진 설명 패키지

## 목적

이 패키지는 STRIX 공개 21개 벤치마크에 대해 S-Structures가 어떤 공학식, 모델링 가정, 생산 코드 모듈과 판정 절차를 사용했는지 한국어로 설명한다. 숫자 비교표만으로는 보이지 않는 `문제 → 식 → 모델 → 엔진 → 결과 → 근거`의 추적 경로를 사람이 검토할 수 있게 하는 것이 목적이다.

## 비파괴 폴더 원칙

- 기존 `01_원자료`부터 `06_검토`까지의 파일은 이동·수정·삭제하지 않는다.
- 각 사례 폴더에는 `07_해석엔진_설명/<ID>_해석엔진_설명보고서.md`만 추가한다.
- 전체 색인과 발표용 자료는 `testreport/STRIX-21-검증/00_설득자료_모음/`에 모은다.
- 공식 21개와 별도인 Cross-Code 사례 XV1·XV2는 `02_추가_교차검증/`으로 분리한다.

## 사례별 보고서 계약

모든 공식 사례 보고서는 다음 항목을 같은 순서로 제공한다.

1. 대표값과 현재 판정
2. 검증 목적과 대표 물리량
3. 경계조건·하중·요소구성을 표시한 모델링 형상도
4. 해석엔진에서 사용한 식
5. S-Structures 모델링 방법
6. 문제 해결 실행 절차
7. 실제 코드 모듈과 역할
8. 이 사례가 보여주는 강점
9. evidence 경로, 한계, 외부 공식 PASS 여부와 재현 방법

생성기는 보고서에 기재한 모든 코드 모듈이 저장소에 실제로 존재하는지 확인하고, 하나라도 없으면 실패한다.

통합 PDF R2는 공식 21개와 XV1·XV2에 각각 벡터 모델링 형상도를 제공한다. 형상도는 개념 설명용이며 원본 모델이 잠기지 않은 6개 사례에서는 공개 자료로 확인된 topology와 검증 의도만 표시한다. 숫자·절점 좌표가 없는 부분을 임의의 동일모델로 주장하지 않는다.

## 판정 경계

- `수치비교 PASS`: 공개 대표 물리량과 로컬 S-Structures 출력을 직접 비교했다.
- `수치 PASS / 적격성 보류`: 대표 수치는 통과했지만 독립 mode vector나 work-balance 같은 qualification 근거가 남았다.
- `체크포인트 PASS`: 생산 엔진 내부의 물리 checkpoint를 통과했다.
- `동등 기준 PASS`: 공개 문제와 같은 종류의 식·허용한계를 적용했다. 절대응답 전체의 동일성을 뜻하지 않는다.
- `기능 PASS / 동일모델 미완료`: 핵심 엔진 모듈은 통과했지만 공개 입력 source lock이 부족하다.
- 외부 공식 qualification은 0/21이며, 문서 어디에서도 이를 외부 공식 PASS로 승격하지 않는다.

## 재생성과 회귀검사

```powershell
npm.cmd run report:engine-package
npm.cmd run test:engine-package
```

재생성 래퍼는 `SSTRUCTURES_REPORT_PYTHON`, Codex 번들 Python, 운영체제 기본 Python 순서로 `reportlab`·`pypdf` 사용 가능 여부를 확인한다. 별도 Python을 쓰려면 환경변수에 실행 파일의 절대경로를 지정한다.

생성 결과는 `package-manifest.json`에 상대경로, 파일 크기와 SHA-256으로 봉인한다. 최종 PDF는 `output/pdf/` 아래의 통합본과 1장 요약본 두 파일이다.

## 발표 자료 사용법

- 의사결정자에게는 1장 요약본을 먼저 제시한다.
- 기술 질의가 나오면 통합 PDF의 해당 사례를 연다.
- 코드 수준 확인이 필요하면 사례별 Markdown의 모듈 경로에서 생산 코드와 검증 runner로 내려간다.
- 6개 입력 미완료 사례는 빈 숫자를 임의 추정하지 않고 필요한 source lock 항목을 설명한다.

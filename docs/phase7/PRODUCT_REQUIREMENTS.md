# Phase 7 Product Requirements

## 1. 목표 사용자와 핵심 작업

| 사용자 | 핵심 작업 | 성공 기준 |
| --- | --- | --- |
| 구조설계 실무자 | 설계조건 설정, 하중·조합 생성, 해석, 결과 비교 | 자동값의 출처와 적용 조건을 확인하고 필요한 값만 수정 가능 |
| 모델 작성 담당자 | 층·그리드·부재 생성, 단면 지정, 하중 입력 | 반복 입력이 적고 연결성·로컬축·누락을 모델링 중 발견 |
| 검토 책임자 | 모델 가정, 조합, 해석법, 경고, 결과 근거 확인 | 보고서만으로 입력 버전과 결과 출처를 재현 가능 |

대표 사용자 작업은 다음 순서다.

1. 프로젝트 단위와 설계기준 판을 선택한다.
2. 구조형식, 층, 그리드, 주요 용도를 설정한다.
3. 필요한 표준 단면을 프로젝트 라이브러리에 담고 사용자 단면을 추가한다.
4. 부재를 생성하고 역할·재료·단면을 일괄 지정한다.
5. 설계조건을 확인해 하중 케이스, 질량원, 하중조합 후보를 만든다.
6. 생성될 항목과 경고를 미리 본 뒤 적용한다.
7. 하중 표시와 검증으로 누락·방향·단위를 확인한다.
8. 1차 선형 또는 명시적으로 선택한 고급 해석을 실행한다.
9. 결과의 조합, 단위, 기준 판, 해석법, 한계를 확인하고 보고서를 만든다.

## 2. 공통 계약

### P7-COM-01 식별자와 표시명 분리

재료, 단면, 하중 케이스, 조합, 해석 케이스는 변경되지 않는 `id`와 사용자가 편집하는 `name`을 분리한다. 이름 변경으로 참조가 깨져서는 안 된다.

### P7-COM-02 단위 계약

저장은 정규 단위로 하고 UI 입력·출력 단위를 별도로 기록한다. 모든 수치 필드는 차원 메타데이터를 가져야 한다. 힘, 길이, 모멘트, 질량, 가속도 사이의 암묵적 fallback은 허용하지 않는다.

### P7-COM-03 출처와 변경 이력

자동 생성 항목은 다음 메타데이터를 가진다.

```json
{
  "origin": "manual | template | rule-pack | imported",
  "sourceId": "KDS-41-12-00@2022",
  "generatedKey": "stable-logical-key",
  "generatedAt": "ISO-8601",
  "userModified": false
}
```

사용자가 생성물을 수정하면 `userModified`가 true가 되고 재생성 시 덮어쓰지 않는다. 미리보기에서 유지·병합·교체를 선택하게 한다.

### P7-COM-04 상태와 경고

모델과 결과는 `verified`, `candidate`, `preliminary`, `unsupported`, `invalid` 중 하나의 상태를 가진다. 경고는 코드, 심각도, 대상 ID, 해결 동작을 포함한다.

### P7-COM-05 Undo와 원자성

템플릿 적용, 층 복제, 단면 일괄 지정, 조합 재생성은 한 번의 undo로 되돌릴 수 있는 transaction이어야 한다. 중간 실패 시 일부만 적용하지 않는다.

## 3. 단면·재료 라이브러리

### 3.1 저장 계층

| 계층 | 의미 | 편집 |
| --- | --- | --- |
| Standard | 기준·제조사·내장 DB, 버전과 출처 고정 | 읽기 전용, 프로젝트로 복제 가능 |
| Office | 사무소 공통 단면·재료 | 관리자 편집, 프로젝트로 가져오기 |
| Project | 현재 모델에서 실제 사용하는 항목 | 프로젝트 사용자 편집 |

동일 표시명이 있어도 ID와 출처로 구분한다. Standard DB 업데이트가 기존 프로젝트 속성을 바꾸지 않도록 프로젝트에는 사용 시점의 snapshot을 저장한다.

### 3.2 형상 계약

| 형상 | 입력 | 필수 계산/저장 | 지원 수준 |
| --- | --- | --- | --- |
| SQUARE | B | A, Iy, Iz, J, Ay, Az | 1급 파라메트릭 |
| RECT | B, H | A, Iy, Iz, J, Ay, Az | 1급 파라메트릭 |
| CIRC | D | A, Iy, Iz, J, Ay, Az | 1급 파라메트릭 |
| H | H, B, tw, tf | A, Iy, Iz, J, 선택 Cw | 1급 파라메트릭/DB |
| BOX | H, B, t 또는 web/flange t | A, Iy, Iz, J | 1급 파라메트릭/DB |
| PIPE | D, t | A, Iy, Iz, J | 1급 파라메트릭/DB |
| C/L/T | 형상 치수 또는 검증된 DB 속성 | A, Iy, Iz, J, 주축 정보 | 제한 지원, warping 한계 명시 |
| GENERAL | 직접 속성 | A, Iy, Iz, J, 선택 Ay/Az/Cw | 고급 사용자용 |

`SQUARE`는 단지 목록에 추가하는 별도 수학 구현이 아니라 `RECT(B=H)`의 명확한 사용자 계약이다. 한 변만 편집하며 B와 H가 어긋나지 않는다.

### 3.3 편집기 요구사항

- P7-SEC-01: 재료·형상·표준명·치수·직접 속성을 검색하고 필터링한다.
- P7-SEC-02: 형상 치수와 로컬 y/z축을 2D 단면 미리보기로 즉시 표시한다.
- P7-SEC-03: 단위 변환 후 실제 저장값과 계산 속성을 함께 보여준다.
- P7-SEC-04: 음수 두께, 겹치는 판, 내경 초과, 0 강성 등 유효하지 않은 입력을 저장 전에 차단한다.
- P7-SEC-05: 파라메트릭 계산값을 직접 속성으로 고정하거나 복제할 수 있다.
- P7-SEC-06: CSV/JSON 가져오기는 열 매핑, 단위, 중복, 오류 행을 적용 전에 미리 보여준다.
- P7-SEC-07: 즐겨찾기, 최근 사용, 프로젝트 사용 중 필터를 제공한다.
- P7-SEC-08: 단면이 참조 중이면 삭제 대신 대체 단면을 선택하거나 사용 위치를 보여준다.
- P7-SEC-09: 해석 엔진이 지원하지 않는 속성은 저장은 가능하더라도 결과에 사용되지 않음을 명시한다.
- P7-SEC-10: 단면 ID를 해석 시 찾지 못하면 `invalid-section-reference`로 해석을 중단한다.

### 3.4 부재 지정 요구사항

- 단일 선택, 다중 선택, 층/그리드/부재 역할 필터, 페인트 지정 지원
- 지정 전 변경 대상 수와 기존/신규 단면 요약 표시
- 부재 위에 단면명, 역할, 로컬축, 회전각을 선택적으로 오버레이
- 기둥은 로컬축 방향을 평면에서 확인하고 90도 회전을 한 동작으로 수행
- 현재 선택 단면의 물성, 지원 수준, 출처를 우측 속성 패널에서 확인

### 3.5 해석 속성 세트와 삽입점

단면 원형 자체를 바꾸지 않고 부재별 해석 가정을 적용할 수 있도록 named property set을 둔다.

- `EA`, `GAy`, `GAz`, `GJ`, `EIy`, `EIz`, 질량, 자중 multiplier를 각각 저장한다.
- 기본값은 모두 1.0이며, 균열단면 등 기준 기반 preset은 출처·적용조건과 함께 제안하고 사용자가 승인한다.
- modifier는 단면 DB 원본이 아니라 부재 또는 프로젝트 property set에 적용한다.
- 단면 삽입점(cardinal point), 로컬축 회전, rigid end zone/offset을 viewport에서 확인한다.
- 보고서와 결과에는 실제 적용된 단면 snapshot과 modifier/offset을 함께 기록한다.
- 재료의 탄성 물성(E, G, 밀도, 열팽창계수)과 설계강도는 분리하며, 강도가 두께 등에 따라 달라지는 재료는 범위표로 저장한다.

### 3.6 KS 강종명과 legacy alias

재료의 내부 ID, 사용자 표시명, KS 강종명, 구명칭 alias를 서로 분리한다.

- P7-MAT-01: 현행 강종은 `standardCode`, `edition`, `designation`, `variant/suffix`, `productForm`, `thicknessRange`를 가진다.
- P7-MAT-02: 신규 프로젝트와 신규 재료 선택기의 기본 목록에는 검증된 현행 KS 강종만 표시한다.
- P7-MAT-03: `SS400`, `SM490` 같은 구명칭은 검색·가져오기용 alias로 인식하되 현재 강종과 같은 물성이라고 가정하지 않는다.
- P7-MAT-04: legacy 프로젝트를 열 때 기존 material ID와 E/G/Fy/Fu/allow 값을 변경하지 않고 `legacy designation` 상태만 표시한다.
- P7-MAT-05: migration preview는 대응 후보, KS 판, suffix, 제품형태, 두께구간, 기존/신규 Fy·Fu 차이, 영향 부재 수를 보여준다.
- P7-MAT-06: migration은 새 canonical material snapshot을 만들고 선택 부재 참조를 한 transaction으로 바꾼다. 취소와 undo가 가능해야 한다.
- P7-MAT-07: `SM490A/B/C`처럼 suffix가 있는 등급은 suffix를 보존한 공식 대응표 없이는 자동 변환하지 않는다.
- P7-MAT-08: 보고서에는 현행 designation 또는 legacy 원명, 적용 KS 판, 실제 사용한 두께구간 물성을 기록한다.

UI에서는 구 프로젝트에 `SS400 (legacy)`처럼 표시하고, 현행 후보를 검색 보조로 보여준다. `SS400 = SS275`처럼 등호로 표시하지 않는다.

## 4. 실무형 모델링

### P7-MOD-01 프로젝트 시작 마법사

입력: 단위, 구조형식, 층 이름·높이, X/Y 그리드 간격, 기준 레벨, 대표 재료.

출력: 빈 그리드 또는 선택한 구조형식의 후보 골조. 생성 전에 절점·부재·층 개수와 기본 역할을 미리 보여준다.

### P7-MOD-02 역할 기반 생성

`column`, `beam`, `brace`, `wall-equivalent`, `slab-equivalent`, `other` 역할을 저장한다. 역할별 기본 재료·단면·단부조건은 프로젝트 템플릿의 제안값이며 사용자가 승인한다.

### P7-MOD-03 층 작업

- 층 삽입, 삭제, 높이 변경, 복제
- 전체 층 또는 선택 그리드만 복제
- 기존 하중·단면·릴리스의 포함 여부 선택
- 위·아래 층 절점 병합 결과 preview

### P7-MOD-04 연결성과 자동 수리

모델링 중 다음 문제를 실시간 또는 명시적 검사로 표시한다.

- 허용오차 내 중복 절점
- 교차하지만 분할되지 않은 부재
- 길이 0 또는 극단적으로 짧은 부재
- 고립 절점/부재
- 단면·재료 미지정
- 기구 가능성이 높은 릴리스 조합
- 층 경계와 어긋난 수직부재

자동 수리는 대상과 영향 목록을 보여주고 transaction으로 적용한다.

### P7-MOD-05 작업공간

패널은 이동, 모서리·가장자리 크기 조절, 좌우 도킹, 자석 스냅, 최소화가 가능해야 한다. 배치는 프로젝트가 아닌 사용자 workspace로 저장하며, 화면 크기 변경 시 보이는 영역 안으로 복구한다. `작업공간 초기화` 명령을 항상 제공한다.

## 5. 하중 케이스와 설계조건

### 5.1 하중 family

| family | 표시명 | 대표 사용 |
| --- | --- | --- |
| D | 고정하중 | 자중, 마감, 고정설비 |
| L | 활하중 | 용도별 바닥 활하중 |
| Lr | 지붕활하중 | 지붕 유지관리 등 |
| S | 적설하중 | 균형·불균형 등 |
| R | 우수하중 | 배수 정체 등 |
| W | 풍하중 | 방향·부호별 케이스 |
| E | 지진하중 | 정적·RSA, 방향·부호·우발편심 |
| H | 토압·지하수압 | 지하외벽, 옹벽 |
| T | 온도·변형하중 | 온도, 수축, 크리프 등 구분 |
| F | 유체하중 | 탱크·수조 |
| EQUIPMENT | 운반·설비하중 | 기계, 크레인, 충격 |
| CONSTRUCTION | 시공하중 | 가설·적치 |
| OTHER | 기타 | 출처와 설명 필수 |

기존 `roof`는 `Lr`, `snow`는 `S` 등으로 명시적으로 migration한다. `OTHER`는 조합 규칙이 자동 추측하지 않는다.

### 5.2 설계조건 마법사

P7-LOAD-01: 다음 질문을 단계적으로 받고 관련 없는 입력은 숨긴다.

- 기준 코드와 판, 설계법
- 건물 용도와 층별 용도
- 구조형식, 중요도, 내진설계 관련 입력
- 지역, 지형·노출, 지반, 적설·풍·지진 입력
- 지붕 사용과 배수 조건
- 지하층, 토압·수압 여부
- 탱크, 크레인, 주요 설비, 온도 또는 시공하중 여부

P7-LOAD-02: 완료 화면은 다음 네 그룹의 diff를 제공한다.

1. 생성/변경할 하중 케이스
2. 생성/변경할 질량원
3. 생성/변경할 하중조합
4. 값이 없어 생성할 수 없는 항목과 사용자가 확인할 경고

P7-LOAD-03: 자동값마다 `값`, `단위`, `출처`, `적용 조건`, `사용자 확인 여부`를 표시한다.

P7-LOAD-04: `미확인` 입력은 0으로 간주하지 않는다. 관련 조합 생성 또는 해석을 차단하거나 명시적으로 제외 승인을 받는다.

### 5.3 프로젝트 템플릿

다음 템플릿을 제공하되 값이 아닌 질문·family·화면 배치를 중심으로 한다.

- RC 업무시설
- RC 공동주택
- RC 학교
- RC 병원
- RC 주차장
- 철골 창고
- 철골 공장/설비 건물
- 일반 빈 프로젝트

층별 용도가 다를 수 있으므로 프로젝트 용도 하나로 모든 바닥 활하중을 덮어쓰지 않는다.

### 5.4 실무 하중 산출 도구

- P7-LOAD-05: D family 안에서 `D-SW`(프로그램 자중)와 `D-SDL`(마감·천장·고정설비 등 추가고정하중)을 구분하고 중복을 검사한다.
- P7-LOAD-06: 바닥 구성 두께·단위중량으로 추가고정하중을 계산하는 산출표를 제공하고 원 항목과 합계를 저장한다.
- P7-LOAD-07: 벽체 두께·높이·단위중량·개구율로 선하중을, 설비 중량·지지점으로 집중/면하중을 만드는 도구를 제공한다.
- P7-LOAD-08: 활하중 패턴은 단순 케이스 복제가 아니라 pattern group과 loaded/unloaded 영역을 stable key로 생성한다.
- P7-LOAD-09: 활하중 저감은 전역 scalar로 임의 적용하지 않고 영향면적·부재 역할·기준 조항·적용 전후 값을 계산 trace로 남긴다.

산출 도구가 만든 값도 일반 자동 생성물과 같이 preview, origin, source, userModified, 재생성 충돌 계약을 따른다.

## 6. 버전 고정 하중조합 엔진

### 6.1 규칙 팩 계약

```json
{
  "id": "KDS-41-12-00@2022",
  "authority": "MOLIT",
  "edition": "2022",
  "amendmentsReviewed": ["MOLIT-2024-846"],
  "publicationStatus": "effective | adopted-not-effective | draft | withdrawn",
  "effectiveDate": "YYYY-MM-DD",
  "verifiedAt": "YYYY-MM-DD",
  "sourceUrls": [],
  "status": "candidate | verified",
  "methods": ["strength", "allowable", "service"]
}
```

정확한 계수표는 공식 원문에서 추출한 fixture와 독립 검토를 통과한 뒤 `verified`가 된다. `draft` 규칙 팩은 비교 화면 외의 자동 생성에 사용할 수 없다. UI 코드에 계수를 직접 넣지 않는다.

### 6.2 생성 요구사항

- P7-COMB-01: 강도, 허용응력, 사용성, 변위, P-Delta, 기초·들림, 질량원 목적을 구분한다.
- P7-COMB-02: 존재하는 family, 선택한 설계법, 적용 조건에 따라 후보를 생성한다.
- P7-COMB-03: 풍·지진 방향과 부호, 우발편심, 동시작용 규칙을 stable key로 확장한다.
- P7-COMB-04: 없는 케이스를 0으로 조용히 넣지 않고 누락 경고와 생성 제외 이유를 보여준다.
- P7-COMB-05: `Preview`, `Merge`, `Replace generated`, `Append custom` 동작을 분리한다.
- P7-COMB-06: 같은 규칙 팩을 재적용해도 중복 조합이 생기지 않는다.
- P7-COMB-07: 사용자 수정 조합은 보호하고 기준 변경 시 차이를 보여준다.
- P7-COMB-08: 신규 빈 모델은 근거 없는 조합을 만들지 않고 `load setup required` 상태로 시작한다.
- P7-COMB-09: 정확한 기본 legacy `CO1(D+L)`은 KDS 후보로 자동 마이그레이션하고 `SLS1`은 사용성 baseline으로 보존한다. 사용자 수정 조합은 자동 변경하지 않는다.
- P7-COMB-10: 보고서에 조합 식, 목적, 규칙 팩, 사용자 수정 여부를 표시한다.

- P7-LUI-01: 현재 하중 케이스와 모든 케이스 보기 모드를 명확히 구분한다.
- P7-LUI-02: 절점/부재/면적/온도/침하 하중을 아이콘과 색으로 구분하고 legend를 제공한다.
- P7-LUI-03: 방향, 로컬/전역 좌표계, 부호, 크기, 분포 범위를 viewport에서 확인한다.
- P7-LUI-04: 선택 부재, 층, 그리드, 역할 기준으로 하중을 복사·이동·스케일·삭제한다.
- P7-LUI-05: 자동 생성 하중과 수동 하중을 구분하고 생성 source로 필터링한다.
- P7-LUI-06: 면적/층하중을 부재로 분배할 때 tributary 영역, 합계, 미분배 잔차를 preview한다.
- P7-LUI-07: 자중은 재료 밀도, 단면 면적, 방향, factor, 포함 케이스를 명시한다.
- P7-LUI-08: 중복 하중, 단위 이상치, 0 하중, 반대 방향, 미참조 케이스를 검사한다.
- P7-LUI-09: 재생성은 사용자가 수정한 하중을 보존하고 변경 충돌을 보여준다.

## 8. 탄성해석 제품 요구사항

### 8.1 선형 정적

- P7-ANA-01: prescribed displacement는 고정/부분 구속 자유도 모두에서 강성방정식에 일관되게 적용한다.
- P7-ANA-02: 분포하중·집중모멘트·온도·offset·release의 fixed-end force와 station 복원을 일관되게 계산한다.
- P7-ANA-03: 인장/압축 전용 활성집합은 비활성화와 재활성화를 모두 허용하고 수렴 이력을 남긴다.
- P7-ANA-04: 힘과 모멘트 평형을 독립적으로 audit하고 단위화 잔차를 보고한다.
- P7-ANA-05: 미지 단면, 특이 강성, 잘못된 단위는 결과 생성 전에 차단한다.

### 8.2 P-Delta

- P7-ANA-06: 화면에서 `1차 선형`, `등가하중 반복(legacy)`, `Direct geometric stiffness`를 실제 실행법과 같은 이름으로 표시한다.
- P7-ANA-07: Direct 결과는 displacement, reaction, member end/station force, axial force, iteration, convergence, combination envelope를 제공한다.
- P7-ANA-08: 다이어프램, generated member, offset/release, unilateral 계약이 정적해석과 동일해야 한다.
- P7-ANA-09: 결과 그래프는 global/story/member와 combination을 분리하고 선택 부재의 단계별 응답을 표시한다.

### 8.3 모달/RSA

- P7-ANA-10: 정적해석과 같은 최종 해석모델, 자유도 축약, 질량원을 사용한다.
- P7-ANA-11: 모드형상, 고유값, 정규화, 질량참여, residual, rigid-body 경고를 저장한다.
- P7-ANA-12: 모드별 절점변위·반력·부재력을 복원하고 각 응답량에 SRSS/CQC를 적용한다.
- P7-ANA-13: 밑면전단력은 지점반력 또는 등가관성력으로 계산하며 변위를 fallback으로 사용하지 않는다.
- P7-ANA-14: RSA scale 적용 전후 값, 목표, factor, 상한·하한, 적용 조합을 추적한다.
- P7-ANA-15: story drift/shear/torsion은 RSA 응답에서 계산하고 정적 케이스를 대체값으로 쓰지 않는다.

### 8.4 sparse, 좌굴, THA

- P7-ANA-16: sparse assembly부터 factorization까지 dense 전체행렬로 되돌아가지 않으며 multi-RHS를 재사용한다.
- P7-ANA-17: 좌굴 해석은 preload 조합을 명시적으로 요구하거나 생성하고 여러 고유값·모드형상을 제공한다.
- P7-ANA-18: THA는 구조 전체 응답 복원과 독립 검증이 끝나기 전 `preliminary`로 표시하며 설계값 자동 전달을 막는다.

## 9. 결과·보고서·검토 흐름

- 결과 선택기는 `해석 케이스 > 조합 > 응답량 > 성분 > 단계/모드` 순으로 일관되게 동작한다.
- 결과가 없으면 빈 그래프 대신 이유와 실행할 동작을 표시한다.
- P-Delta, RSA 등 여러 결과군을 같은 이름으로 덮어쓰지 않고 명확히 분리한다.
- 결과 패널은 이동·도킹·크기 조절 가능하고 선택 부재와 양방향으로 동기화된다.
- 보고서에는 모델 해시, 단위계, 기준 판, 규칙 팩, 해석 옵션, convergence, 경고, 한계를 기록한다.
- `preliminary` 또는 `unsupported` 결과는 상태 표시 없이 설계요약으로 승격할 수 없다.

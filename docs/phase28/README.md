# Phase28 — 기준 개정과 기능 추가를 위한 모듈 경계 점검

2026-09-14 · v1 · **측정 기반 점검 + 적용 완료분 기록**

목표는 "모듈화가 잘 돼 있나"가 아니라 답할 수 있는 질문이었다: **KDS 조항 하나가 개정되면 몇 곳을 고쳐야 하고, 영향 범위를 어디서 확인하는가.**

## 측정 결과

| 항목 | 값 |
| --- | --- |
| 조항을 인용하는 모듈 | 38 |
| 인라인 조항 선언 | 50~54 (파일 39개) |
| 기준값+단위+조항을 한 행에 선언하는 모듈 | **1 / 38** |
| 중앙 검토 지도와 모듈의 인용 불일치 | **16** |
| 어떤 러너도 실행하지 않는 시험 파일 | **9** |

## 확인된 문제

### 1. 조항 정보가 두 곳에 다른 정밀도로 존재한다

`designCodeBasis.targets`는 검사별 `[문서, 조항]`을 거친 수준으로 갖고(`'rc-torsion': [['142022','4']]`), 각 검사 모듈은 정밀한 조항을 인라인으로 붙인다(`clause:'4.5.4(5)'`). 같은 사실의 두 기록이라 **어긋났다 — 16건.**

피해는 판정이 아니라 **영향 범위 산정**이다. `applied` 상태는 모듈 자체 참조로 결정되므로 계산은 정상이지만, 중앙 지도로 개정 영향을 검토하면 `rc-shear-y`가 KDS 14 20 10에 의존한다는 사실이 보이지 않는다.

### 2. 기준 수치가 단위까지 뒤섞여 흩어져 있다

같은 300mm 제한이 한 모듈에서는 `300`(mm), 다른 모듈에서는 `.3`(m)이다. 개정 시 모듈마다 단위를 확인해야 한다.

**다만 좋은 패턴이 이미 저장소 안에 있다.** `kdsJointHoops.js`는 기준 요구사항을 선언적 행으로 갖는다:

```js
{id:'horizontal-spacing', limit:.35, unit:'m', clause:'4.5.4(3)', relation:'maximum', ...}
```

값·단위·조항이 한 줄에 있고 `repairKind`까지 연결된다. 문제는 **38개 중 1개만** 이 형태라는 것이다.

### 3. 어떤 게이트도 실행하지 않는 시험이 있었다

phase 러너는 파일명 규칙으로, 마일스톤 러너는 package script로 시험을 찾는다. 두 규칙 밖의 이름을 가진 파일은 **집이 없었다.** 9개가 그랬고 그중 `m46-representative-pdf-refresh`는 **실패한 채 방치**돼 있었다. Phase26이 phase 16~25에서 다룬 것과 같은 문제가 파일명 차원에서 남아 있던 것이다.

## 적용한 것

- **중앙 검토 지도 보강** — 모듈이 실제로 선언한 조항을 근거로 14개 검사에 누락 문서를 채웠다. 값은 모듈에서 가져왔고 새로 만들지 않았다. 불일치 16 → 4.
- **드리프트 차단 검사** (`p28-code-reference-consistency`) — 비대칭이다. 모듈이 인용하는 문서가 검토 지도에 없으면 **실패**하고, 지도가 문서를 더 나열하는 것은 허용하고 보고만 한다. 검토 목적상 넓은 쪽은 안전하기 때문이다.
- **미분류 시험 러너** (`run-unphased-tests`) — 어떤 규칙에도 걸리지 않는 파일을 실행한다. 목록을 커버리지 검사에서 그대로 받으므로 새 파일이 자동으로 편입된다.
- **커버리지 차단 검사** (`p28-test-gate-coverage`) — 859개 전부 실행됨을 보장하고, 미분류 집합이 늘어나면 실패한다. 그곳이 "아무거나 쌓이는 곳"이 되지 않게 상한을 뒀다.
- `m46` 실패 해결 — 보고서 색인을 재생성해 현행 버전을 담게 했다.

## 남은 것 — 판단이 필요하다

**기준 수치의 선언화**가 남았다. 두 방향이 있다.

**A. 선언적 행 패턴을 확산** — `kdsJointHoops` 형태로 37개 모듈을 수렴시킨다. 값·단위·조항이 사용 지점에 함께 있어 검토가 쉽다. 다만 개정 시 여전히 여러 파일을 열어야 하고, 수치 민감 코드를 광범위하게 건드리는 작업이다.

**B. 모듈이 자기 기준 참조를 export하고 중앙 지도를 생성** — 저장소는 이미 `kdsClauseIndex.js`를 생성물로 관리하는 선례가 있다. 단일 출처가 모듈이 되고 중앙 지도는 파생되므로 드리프트 자체가 사라진다. 대신 38개 모듈에 export를 추가해야 한다.

현재는 **A의 좋은 사례가 1개, 드리프트는 검사로 차단**된 상태다. 두 방향 모두 이번에 추가한 검사가 안전망 역할을 하므로 나중에 점진적으로 진행할 수 있다.

# 공개 개발판 처리 한도 확대

사용자 요청: 관리 메모리1GiB, 통합 상세검토300부재까지 허용.

| 항목 | 이전 | 변경 |
|---|---:|---:|
| 관리 메모리 상한 | 256MiB | 1024MiB |
| 탄성 Worker 작업영역 허용 추정치 | 512MiB | 1024MiB |
| 상세검토 부재 | 30 | 300 |
| 조합별 계산 위치 | 300 | 6300 |
| 후보 재해석 절점 상한 | 120 | 600 |
| 단일 상세검토 timeout | 10초 | 120초 |

6300개 위치는 **기본21개 위치/부재 × 300부재**를 수용한다. 세분화 모델은 위치 합계 제한이 먼저 적용될 수 있다. 600절점도 실제 행렬·Worker 작업영역 및 공유 메모리 예산 검사를 통과해야 한다.

1GiB를 시작 시 할당하지 않는다. 모델·결과·임시 작업의 보수적 관리 추정치 상한이며 실제 브라우저 전체 힙/RSS 제한은 아니다. Worker 허용 추정치는 별도 검사로 공유 관리 예산과 자동 합산한 총RSS 보장을 의미하지 않는다. 메모리 초과, 취소, 종료 미확인 Worker 격리와 결과 해제 검사는 유지한다. GPU 버퍼·비선형 전송 예산은 이번 탄성/상세검토 요청과 별도라 변경하지 않는다.

후보 탐색은10초의 제한된 작업 단위와16개 후보를 유지한다. 결과 페이지50행, WebMCP 응답·다운로드 조각 크기, 최대8조합 및 PDF권당60쪽 제한도 유지한다. 조회 context의 timeout을 실제 실행 제한과 연결했다.

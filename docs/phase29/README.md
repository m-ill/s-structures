# Phase29 — 일반 기준설계의 세 공백 구현

2026-09-14 · 계획 v1 · **착수 전**

Phase28까지 정리하면서 확인된 커버리지 공백 세 가지를 정식 검토 경로에 올린다. 기존 39종 실무 검사와 같은 계약(검사 id · 구현 모듈 · KDS 문서 · 적용 범위)을 따르며 새 구조를 만들지 않는다.

| 공백 | 현재 상태 | 목표 |
| --- | --- | --- |
| G1 슬래브·벽 설계 | `detailRcSlab`/`detailRcWall`은 있으나 **실무 검사 39종에 없음** (예비 산정 전용) | 슬래브·벽을 검사 경로에 올린다 |
| G2 활하중 저감 | `kdsLoadCombinations`에 필드만 선언(`required:false`) | KDS 41 12 00 §3.5를 실제로 적용한다 |
| G3 내진 기준 계수 | 지반분류·R·S_DS를 사용자가 입력 | KDS 41 17 00에서 도출한다 |

## 원문 확보 상태 — 추가 수집 불필요

세 공백 모두 근거 문서가 **이미 로컬에 있다.** Phase25가 공개 KCSC endpoint에서 확보해 뒀다.

| 문서 | 위치 | 규모 |
| --- | --- | --- |
| KDS 41 12 00 건축물 하중기준 | `verification/evidence/phase25/kcsc/official-20260911/KDS-411200-official.json` | 1,577항목 · 조항색인 185 |
| KDS 41 17 00 건축물 내진설계기준 | `.../KDS-411700-official.json` | 조항색인 420 |
| KDS 14 20 xx 콘크리트구조 | `verification/evidence/phase24/kcsc/*-text.txt` | 9개 문서 |

**결정적 제약**: 확보된 본문은 조항 구조와 산문은 온전하지만 **수식은 이미지라 텍스트에 없다.** 예를 들어 §3.5.1(1)은 "표 3.2-1의 기본등분포활하중에 활하중저감계수를 곱하여 저감할 수 있다"까지 있고 식 (3.5-1)은 `(3.5-1)`이라는 표기만 남는다.

그래서 이 페이즈의 규칙은 다음과 같다.

> **조항 존재와 산문에서 읽히는 값은 원문을 근거로 구현한다. 수식은 원문에 없으므로 별도로 확정하고 그 출처를 기록한다. 수식을 추정해서 넣지 않는다.**

이것은 저장소가 이미 쓰는 경계다 — "원문·조항 제목 존재 확인은 해당 식의 구현 정확성을 입증하지 않는다".

### 산문에서 직접 읽히는 값 (구현 가능)

KDS 41 12 00 §3.5:

- 적용 문턱: 지붕활하중 제외, **영향면적 36m² 이상**
- 영향면적: 기둥·기초 = 부하면적 **×4**, 보·벽체 = **×2**, 슬래브 = **×1**. 캔틸레버 부분은 배수 없이 단순 합산
- 하한: 1개 층 지지 부재 **C ≥ 0.5**, 2개 층 이상 지지 부재 **C ≥ 0.4**

저감계수 산정식 (3.5-1) 자체만 확정 대상이다.

## 마일스톤

### M0 · 근거 정리와 착수 기준선

1. 세 공백의 조항을 원문에서 추출해 `-text.txt` 관례로 기록한다(41 12 00, 41 17 00).
2. **수식 확정 목록**을 만든다. 각 항목에 조항 번호, 산문으로 확인된 조건, 확정이 필요한 식, 확정 출처.
3. 현재 커버리지를 기준선으로 남긴다. Phase28에서 만든 `check-code-reference-consistency`가 새 문서를 인식하는지 확인한다.

**완료 조건** — 수식 확정 목록이 나오고, 각 항목이 "산문 근거 있음/식 확정 필요"로 분류된다.

### M1 · G2 활하중 저감 (가장 작고 독립적)

부하면적은 이미 계산 경로가 있다(기둥 부담면적, 슬래브 하중 분배). 여기에 영향면적 배수와 하한을 얹는다.

1. 부재 역할별 영향면적 산정(기둥·기초 ×4, 보·벽 ×2, 슬래브 ×1, 캔틸레버 합산).
2. 36m² 문턱과 0.5/0.4 하한 적용.
3. 저감계수 식은 **확정된 출처를 받은 뒤** 연결한다. 그 전까지는 `LIVE_LOAD_REDUCTION_FORMULA_REQUIRED`로 미검토를 반환하고 **저감 없이(보수적으로) 진행**한다.
4. 적용 여부와 계수를 하중 감사(`loadAudit`)에 기록한다. 저감은 결과를 **줄이는** 방향이므로 근거 없이 조용히 적용되면 안 된다.

**완료 조건** — 저감 적용/미적용이 부재별로 추적 가능하고, 식이 없으면 저감하지 않는다.

### M2 · G3 내진 기준 계수

`importanceFactor`는 이미 입력 필드이고 응답스펙트럼·밑면전단 스케일·층간변위는 구현돼 있다. 비어 있는 것은 **입력을 건물 조건에서 도출하는 앞단**이다.

1. 지반분류 — 전단파속도 등 지반 정보에서 분류를 도출. 정보가 없으면 도출하지 않고 사유를 반환한다.
2. 지진위험도·설계스펙트럼가속도 — 지역과 지반분류에서 도출.
3. 시스템 계수 — 구조시스템 선언에서 도출. 시스템 판정 자체는 사용자 선언을 신뢰하되 **선언과 실제 배치의 불일치는 검사**한다.
4. 중요도 — 용도에서 도출.

각 단계는 **도출 결과와 사용된 입력을 함께 반환**한다. 도출할 수 없으면 사용자 입력을 그대로 쓰되 "도출되지 않음"을 표시한다.

**완료 조건** — 사용자가 넣은 값과 도출된 값을 구분해 볼 수 있고, 불일치가 보인다.

### M3 · G1 슬래브 설계

**판·쉘 FEM에 의존하지 않는다.** 직사각 패널 정확도 결함으로 릴리스가 차단된 경로이며, 기준 설계법은 FEM 없이도 성립한다.

1. 일방향 슬래브 — 단위폭 스트립의 휨·전단·최소철근·간격·피복. 보 검사 모듈을 폭 1,000mm 단면으로 재사용할 수 있는지 먼저 확인한다(새 계산 엔진을 만들지 않는다).
2. 연속 슬래브 — 경간 중앙 하부철근과 지지부 상부철근을 구간으로 구분.
3. 직교방향 철근과 개구부 추가철근.
4. 이방향 거동 — **별도 결정 필요**. 계수법을 구현할지, FEM 결함 해결을 선행할지. 결정 전까지 이방향은 `NOT_CHECKED` + 사유.

**완료 조건** — 일방향 슬래브가 실무 검사 목록에 등록되고, 제공 배근에 대해 판정이 나온다. 이방향은 명시적 미검토.

### M4 · G1 벽 설계

`detailRcWall`은 PM 곡선을 이미 쓴다. 기둥 검사 경로와 공유 가능한 부분을 먼저 식별한다.

1. 면내 휨·축력(경계요소 포함 여부 판단 필요), 면내 전단, 최소 수직·수평 철근비.
2. 구조벽 내진 상세는 **범위 선언 후** 단계적으로.

**완료 조건** — 벽이 검사 목록에 등록되고 적용 범위가 명시된다.

### M5 · 등록과 게이트 편입

1. 새 검사를 `practicalRuleImplementations`에 등록(검사 id·모듈·문서·범위).
2. `designCodeBasis` 검토 지도에 조항 추가 — Phase28 검사가 누락을 잡는다.
3. 새 시험을 게이트에 편입. 파일명 규칙을 따르면 자동 편입되고, 아니면 미분류 러너가 받는다.

## 순서 근거

G2 → G3 → G1 순이다. G2는 기존 하중 경로에 얹는 작은 작업이고, G3는 입력 도출이라 해석 엔진을 건드리지 않는다. G1은 새 부재 종류의 검사 경로라 가장 크고, 이방향 결정이 걸려 있다.

## 이 페이즈가 하지 않는 것

- 판·쉘 FEM의 직사각 패널 정확도 결함 해결. 별도 과제이며 M3는 그것에 의존하지 않는다.
- 수식 추정. 원문에 없는 식은 확정 출처를 받아 넣는다.
- 설계 전달 승인. `designTransferAllowed`는 계속 false다.

## 경계

검사 추가는 계약 확대이지 구조설계 승인이 아니다. 새 검사가 OK를 반환해도 외부 독립 검증은 별개다.

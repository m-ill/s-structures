## 원칙

Phase29의 규칙은 하나였다.

> 조항과 산문에서 읽히는 값은 원문을 근거로 구현한다. 수식이 이미지라 원문에 없으면 별도로 확정하고 그 출처를 기록한다. **추정해서 넣지 않는다.**

확정이 필요했던 항목은 7건이었고, 오너가 공개 기준 원문·이미지를 직접 대조해 **7건 모두 확정**했다. 확정값은 결과 객체에 출처와 함께 실린다.

## M1 · G2 활하중 저감 — `src/loads/liveLoadReduction.js`

```
C = 0.3 + 4.2 / √A     (A = 영향면적 ≥ 36 m²)
```

**C는 남겨서 적용하는 비율이다.** 검산: 부하면적 36 m² 기둥 → A = 144 → C = 0.65.

조항 해석이 걸린 곳이 하나 있었다. §3.5.3(3)은 집회용도를 **5 kN/m² 이하**로만 한정하므로, 초과분은 §3.5.3(2)가 지배한다.

| 집회용도 활하중 | 지지 층수 | 결과 |
| --- | --- | --- |
| ≤ 5 kN/m² | 무관 | 저감 불가 |
| > 5 kN/m² | 1개 층 | 저감 불가 |
| > 5 kN/m² | 2개 층 이상 | C = 0.8 |

마지막 줄은 **문언 해석이고 별도 질의회신이 없다.** 하중을 줄이는 방향이라 그 사실이 결과의 `interpretation`에 함께 실린다.

**하중 감사 연결** — `buildLoadAudit`이 선언을 믿지 않고 다시 계산한다:

| 코드 | 심각도 |
| --- | --- |
| 근거 선언 없는 저감 계수 | **error** |
| 선언과 다른 계수(낡은 값) | **error** |
| 조항상 저감 안 됨 | info + 사유 |

## M2 · G3 내진 기준계수

**`seismicImportance.js`** — KDS 41 10 05 §3 용도·규모 분류 → KDS 41 17 00 표 2.2-1(특 1.5 / I 1.2 / II 1.0). 도출값을 사용자 입력 옆에 나란히 보고하고, 중요도(2)는 §3.3(1)의 **잔여 분류**임을 표시한다 — 아무 규칙에도 안 걸려서 여기 오는 것과, 용도가 아예 선언되지 않아 도출이 안 되는 것은 다르다.

**`seismicSiteClass.js`** — 표 4.2-4 지반분류, 식 (4.2-1) 토층평균전단파속도, 표 4.2-1/4.2-2 지반증폭계수.

```
Vs,soil = Σd_i / Σ(d_i / Vs_i)      주행시간 평균이지 산술평균이 아니다
```

오너 검토에서 두 가지가 구현을 바꿨다:

- **S₆에는 표 계수가 없다.** S₅ 행을 빌려 쓰면 값을 지어내는 것이므로 `NOT_CHECKED` + `S6_REQUIRES_SITE_RESPONSE_ANALYSIS`를 반환한다.
- **KDS 17 표만 구현하면 건축물 수정 규정이 빠진다.** §4.1.1(1)①②③, §4.1.3, §4.2.2(2)(3)을 모두 반영했다. "적용할 수 있다"인 완화 규정은 **opt-in**이고, 적용되면 조항과 효과가 결과에 남는다. 완화는 수요를 낮추는 방향이다.

§4.2.1.2(4) 부지고유 조건은 깊이·속도 표보다 **먼저** 판정한다. 액상화 지반이나 기반암 50 m 초과가 깊이·속도만으로 통과하지 않는다.

**`seismicSystemCoefficients.js`** — 표 6.2-1 RC 12행. 열 순서는 R, Ω₀, C_d.

**시스템 구분 + 세부 시스템의 복합 키**다. 같은 RC 보통전단벽이 내력벽 4 / 건물골조 5 / 이중(특수) 6 / 이중(중간) 5.5 / 상호작용 4.5로 갈린다. 세부 시스템만 주면 값을 고르지 않고 후보 5개를 돌려준다.

## M3 · G1 슬래브

**`slabStripReview.js`** — 일방향 슬래브를 **단위폭 1 m 스트립**으로 보고 기존 `evaluateKdsSection`에 통과시킨다. 새 휨 엔진을 만들지 않았다. 전단은 기초판 경로를 따르며 KDS 14 20 22 §4.3.3(1) 최소전단철근 면제를 함께 기록한다.

검사 5종: 두께 · 휨 · 일방향전단 · 철근간격 · 수축온도철근.

**`slabCoefficientMethod.js`** — 이방향은 계수법으로 구현했다. 판·쉘 FEM에 의존하지 않는다.

```
Ma⁻ = C_A,neg · wu · l₁²                    wu = 1.2D + 1.6L
Ma⁺ = (C_A,DL·1.2D + C_A,LL·1.6L) · l₁²     DL·LL 계수를 각각 적용해 합산
```

계수표 복원이 이 마일스톤의 핵심이었다. 평문 텍스트는 빈칸을 뭉개서 **어느 계수가 단변인지 장변인지를 잃는다.** 원문 HTML은 각 Case 셀이 `colspan=3`에 `<p>` 3개를 품고 있어 빈칸 위치가 그대로 남아 있었다. 네 표 전부(11 경간비 × 9 Case) 복원했다.

Case 1~9 지지조건 그림은 **셀 테두리로 그려져 있어 수집본에 없었고**, 오너가 공개 도면에서 공급했다. 병합은 믿지 않고 검증했다 — *굵은 변이 있는 방향에는 반드시 부모멘트 계수가 있어야 한다*:

```
99 / 99 일치
```

그림과 표의 빈칸이 서로를 독립적으로 확인한다.

원문 인쇄 결함 4건은 **값을 고치지 않고 표시만** 했다. 그중 수치 2건(`0066`, 단조성을 깨는 `0.025`)은 해당 셀이 계산에 쓰이면 모멘트를 내지 않고 `COEFFICIENT_PRINTED_DEFECTIVELY_IN_SOURCE`로 차단한다.

## M4 · G1 벽체 — `src/design/rc/wallSectionReview.js`

검사 6종: 두께 · 최소수직철근비 · 최소수평철근비 · 철근간격 · 철근층 · 설계축강도.

§4.2(3)①은 상수가 아니라 식이다 — `0.0020 × 400 / fy`, 식 안에서 fy는 500 MPa로 제한.

식 (4.3-1)은 이미지였고 오너가 확정했다:

```
φPnw = 0.55 · φ · fck · Ag · [1 − (k·lc / 32h)²]      φ = 0.65
```

**φ가 식 안에 있으므로 결과는 이미 설계강도다.** 다시 곱하지 않는다는 사실을 `strengthReductionFactorAlreadyApplied`로 표기한다. lc는 받침부 사이 수직길이, h는 **벽체 두께**(층고가 아니다).

§4.3.2(1) 적용조건을 먼저 판정한다. 합력이 두께 중앙 1/3(|e| ≤ h/6)을 벗어나면 **합격·불합격을 판정하지 않고** `RESULTANT_OUTSIDE_MIDDLE_THIRD`를 반환한다 — 벽체가 불합격인 게 아니라 이 식이 맞는 도구가 아니기 때문이다.

## 수축·온도철근비 — 사유를 정정했다

KDS 14 20 50 §4.6.2(1)②도 확정돼 구현했다.

```
fy <= 400       rho = 0.0020
fy >  400       rho = max(0.0020 * 400/fy, 0.0014)
```

| fy | 0.0020 x 400/fy | 하한 적용 후 |
| --- | --- | --- |
| 400 | 0.0020 | 0.0020 |
| 500 | 0.0016 | 0.0016 |
| 600 | 0.001333 | **0.0014** |

**앞서 이 항목을 "400 MPa 값을 대입하면 과소평가"라고 기록했는데 반대였다.** 식은 fy가 커질수록 작아지므로, 0.0020을 대신 쓰면 요구량을 **과대** 산정한다. 대입하지 않은 처리 자체는 옳았지만 — 이 조항은 최소값이고, 기준보다 조용히 더 요구하는 것도 그 나름의 결함이다 — 사유는 틀렸으므로 정정했다.

철근비의 분모는 **전체 콘크리트 단면적 b·h**다(b·d가 아니다). §4.6.2(2)의 1,800 mm²/m는 **요구량의 상한**이지 배근량의 상한이 아니며, §4.6.1(3) 심한 구속 조건은 최소량을 늘리라는 규정이라 미평가로 표시한다.

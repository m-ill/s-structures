# Phase29 진행 상태

2026-09-14 · **M1 완료 · M0/M2/M3/M4 미착수**

## M1 · G2 활하중 저감 — 완료

KDS 41 12 00 §3.5를 `src/loads/liveLoadReduction.js`에 구현하고 하중 감사에 연결했다.

### 저감계수

```
C = 0.3 + 4.2 / sqrt(A)      A = 영향면적 [m²]
```

**C는 남겨서 적용하는 비율이다.** C = 0.65면 기본활하중의 65%를 쓴다. 줄이는 양이 아니다. 이 문장은 결과 객체의 `basis` 필드에 그대로 들어간다.

식 (3.5-1)은 확보된 원문에서 이미지라 텍스트에 없다. 오너가 공개 기준 이미지와 대조해 확정했고, 그 사실이 모든 결과의 `equation.origin`에 기록된다. Phase29 규칙대로 **추정하지 않고 확정 출처를 기록**한 것이다.

### 산문에서 읽어 구현한 값

| 항목 | 값 |
| --- | --- |
| 영향면적 배수 | 기둥·기초 ×4, 보·벽 ×2, 슬래브 ×1 |
| 캔틸레버 | 배수 없이 단순 합산 |
| 적용 문턱 | 영향면적 36 m² 이상 |
| 하한 | 1개 층 지지 C ≥ 0.5, 2개 층 이상 C ≥ 0.4 |
| 5 kN/m² 초과 | 저감 불가, 단 2개 층 이상 지지 시 C = 0.8 |
| 집회 용도 | 저감 불가 (층수 무관) |
| 승용차 주차장 | 저감 불가, 단 2개 층 이상 지지 시 C = 0.8 |
| 일방향 슬래브 | 폭 ≤ 1.5 × 경간 |
| 지붕활하중 | §3.5 범위 밖 |

검증 예제: 부하면적 36 m² 기둥 → A = 144, C = 0.3 + 4.2/12 = **0.65**.

### 입력이 없으면 저감하지 않는다

역할·부하면적·지지층수·활하중 강도 중 하나라도 없거나 쓸 수 없으면 `factor = 1`로 되돌리고 사유를 남긴다. 저감은 결과를 **줄이는** 방향이라 조용히 일어나면 안 된다.

### 하중 감사 연결

`buildLoadAudit`이 `model.liveLoadReduction` 선언을 **다시 계산해서** 대조한다. 선언을 믿지 않으므로 낡은 계수도 잡힌다.

| 코드 | 심각도 | 조건 |
| --- | --- | --- |
| `live-load-reduction-undeclared` | **error** | 하중에 1 미만 계수가 붙었는데 근거 선언이 없다 |
| `live-load-reduction-mismatch` | **error** | 붙은 계수가 선언이 산출하는 계수와 다르다 |
| `live-load-reduction-not-applied` | info | 선언은 있으나 조항상 저감되지 않는다 (사유 기록) |

근거 없는 저감은 warning이 아니라 **error**다. 감사 상태가 `invalid`이 된다.

### 등록

`kdsLoadCombinations`의 `designInputs`에서 `liveLoadReduction`은 선언만 있던 항목이었다. 이제 `implementation`(모듈·문서·조항·감사 모듈·적용 범위)을 갖는 유일한 항목이며, 시험이 이 등록을 지킨다. 나머지 항목은 여전히 사용자 입력이고 그 차이가 필드로 드러난다.

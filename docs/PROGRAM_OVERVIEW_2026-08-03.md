## 1. 한눈에 보는 결론

S-Structures는 브라우저 기반 3D 구조 모델링, 선형 탄성해석, 하중조합, 결과 시각화, 예비 설계검토와 계산서 생성을 하나의 작업 흐름으로 연결한 구조 검토 프로그램이다.

현재 성숙도는 **기능 베타, 운영 로컬 파일럿**으로 판단한다. 주요 기능은 실제로 연결되어 있고 Windows 단일 PC에서 내부 파일럿을 운영할 수 있을 만큼 보안·데이터·백업 절차가 검증됐다. 다만 외부 상용 해석기 및 독립 수계산과의 교차검증이 완결되지 않았으므로, 최종 구조설계·인허가·설계전이 또는 공개 서비스 용도로 사용할 단계는 아니다.

| 사용 목적 | 현재 판단 | 조건 |
| --- | --- | --- |
| 교육, 연구, 기능 데모 | 가능 | 결과의 적용 범위를 사용자에게 고지 |
| 단일 PC 내부 구조검토 파일럿 | 조건부 가능 | Windows, loopback-only, 담당자 검토, 정기 백업 |
| 기밀 자료를 이용한 내부 파일럿 | 조건부 가능 | 외부 상태 폴더 사용, 가입 차단, 접근·백업 정책 준수 |
| 사내 LAN 다중사용자 서비스 | 불가 | TLS, 환경별 보안검증, 운영 DB와 권한체계가 추가로 필요 |
| 공개 인터넷·SaaS 서비스 | 불가 | 테넌트 격리, WAF, 관제, 외부 보안검토 등이 필요 |
| 최종 계산서, 실시설계, 인허가 제출 | 불가 | 외부 공학 교차검증과 책임기술자 승인 게이트 미완료 |

## 2. 프로그램의 목적

S-Structures의 핵심 목적은 구조 엔지니어가 초기 아이디어를 3D 골조로 빠르게 표현하고, 모델·하중·해석·검토·보고서 사이의 단절을 줄이는 것이다. 단순히 해석 결과 숫자만 출력하는 것이 아니라 다음 정보를 같은 프로젝트 흐름에 묶는 데 초점을 둔다.

- 모델을 어떤 단위·재료·단면·경계조건으로 만들었는가
- 어떤 하중케이스와 하중조합을 적용했는가
- 어떤 해석 조건과 근거로 결과가 생성됐는가
- 어떤 부재와 조합이 지배적인가
- 무엇이 통과·주의·실패 또는 미지원 상태인가
- 결과와 계산서가 동일한 모델·해석 기록에서 만들어졌는가
- 프로젝트 리비전, 승인과 배포 이력이 서로 일치하는가

즉, 현재 제품의 정체성은 **최종 설계를 자동으로 대신하는 프로그램**이 아니라 **구조 검토의 계산 과정과 판단 근거를 투명하게 연결하는 디지털 노트 및 파일럿 플랫폼**에 가깝다.

## 3. 대표 작업 흐름

```text
프로젝트 생성
  → 3D 골조 모델링
  → 재료·단면·지점·부재 연결조건 정의
  → 하중케이스·하중조합 작성
  → 선형 탄성해석 및 조건부 고급해석
  → 변형·부재력·반력·포락 결과 확인
  → 예비 응력·세장비·처짐 검토
  → 계산 근거와 주의사항 확인
  → 보고서·PDF·프로젝트 파일 생성
  → 리비전 검토·승인·릴리스·백업
```

모델과 결과는 브라우저 화면에서 3D로 확인할 수 있으며, 프로젝트 JSON과 계산서 형태로 보존할 수 있다. 로컬 파일럿판은 프로젝트 리비전, 승인 상태, 업로드 자료와 백업·복구까지 서버 작업 흐름으로 관리한다.

## 4. 주요 기능

### 4.1 3D 모델링과 편집

- 격자, 절점과 부재를 이용한 3D frame/truss 모델 생성
- X/Y/Z 축 및 작업면 스냅, 층 복사, 기둥 자동 생성
- 박스 다중 선택, 복사·붙여넣기, 실행취소·재실행
- 부재별 재료, 단면, 역할, 단부 연결조건과 설계 속성 지정
- 회전단·이동단·고정단 및 6자유도 개별 구속
- 모델과 함께 회전·확대되는 손글씨 메모

### 4.2 하중과 조합

- 고정하중, 활하중, 풍하중과 지진하중 계열의 하중케이스 관리
- 절점하중, 부재하중과 자중 반영
- 강도·사용성 조합, 사용자 조합과 결과 포락
- 하중 스텝 재생 및 조합별 지배 결과 추적
- KDS-style 조합 registry, 규칙 적용 기록과 산정 trace

KDS-style 기능은 구조화된 프리셋과 추적 기능이며, 모든 설계기준 세부 절차를 완전히 자동화한 법규 엔진은 아니다.

### 4.3 구조해석

핵심 해석은 3차원 프레임 요소 기반 직접강성법을 사용한다. 각 절점의 6자유도와 부재의 축력·비틀림·2축 휨을 취급하며, 총하중과 총반력의 평형 및 해석 잔차를 함께 확인한다.

| 해석 영역 | 현재 상태 | 해석 시 주의사항 |
| --- | --- | --- |
| 3D frame/truss 선형 정적 | 핵심 사용 가능 | 현재 내부 파일럿의 주 생산 범위 |
| 하중조합·포락 | 사용 가능 | 입력 조합과 설계기준 적합성은 담당자가 확인 |
| Direct P-Delta | 구현·검증 경로 보유 | 지원 요소와 해석 조건을 벗어나면 결과 승격 차단 |
| 모달·응답스펙트럼 | 구현·검토 가능 | 기준별 후처리와 외부 교차검증이 추가로 필요 |
| 탄성 좌굴 | 구현·검토 가능 | 비탄성 좌굴 또는 미지원 요소는 최종 근거로 사용 금지 |
| 선형 시간이력 | 검토 단계 | 최종 동적 설계 근거로 사용 금지 |
| pushover·비선형 시간이력 | 예비 workflow | 정식 비선형 반복해석 엔진으로 간주하지 않음 |
| flat-shell, 고급 요소 | 구현·자격검증 진행 | Phase 10 외부 검증 게이트가 차단 상태 |

### 4.4 결과 시각화

- 변형 형상과 부재 내부 처짐곡선
- 축력, 전단력, 2축 휨모멘트와 비틀림 다이어그램
- 지점반력 및 하중-반력 평형 확인
- 하중케이스·조합별 결과 전환과 결과 포락
- 부재 검정비 색상 표시와 지배조합 확인
- 모달, 좌굴과 일부 동적 결과의 그래프·표시

### 4.5 예비 설계검토

- 허용응력 기반 축력·휨 상호작용 검토
- 전단 검토
- 기둥·가새의 `KL/r` 세장비 스크리닝
- 보 처짐 `L/Δ` 검토
- 부재별 OK·WARN·NG 분류와 지배조합 추적
- RC 배근, 철골 부재, 접합과 기초의 예비 schedule·review trace

OK·WARN·NG는 현재 프로그램이 지원하는 식과 입력 범위 안의 **예비 검토 신호**다. 횡좌굴, 국부좌굴, 접합부 상세, 내진 상세, 기초 지내력·침하 등 미완 절차까지 포함한 최종 안전 판정이 아니다.

### 4.6 보고서와 데이터 교환

- 화면 및 전체 페이지 PDF 출력
- 모델·설정·하중·결과를 포함하는 프로젝트 JSON
- 한·영 계산서와 대표 건물 계산 패키지
- 모델·분석 기준·산정 trace·주의사항을 연결한 상세 보고서
- MIDAS Gen용 MGT 내보내기
- 프로젝트 리비전, 승인과 릴리스 기록
- 백업 생성 및 빈 상태 폴더로의 복구

일부 DWG, 도면 이미지, 점군과 MGT 가져오기는 미완 또는 예비 단계다.

## 5. 프로그램 구성

| 구성 요소 | 역할 |
| --- | --- |
| 브라우저 UI | 3D 모델링, 속성 입력, 해석 실행, 결과 시각화와 보고서 접근 |
| 해석·설계 모듈 | frame/truss 해석, 조합·포락, 조건부 고급해석과 예비 설계검토 |
| 로컬 서버 | 계정, 프로젝트, 파일 업로드, 리비전, 승인·릴리스와 백업 관리 |
| 상태 저장소 | 설치 파일과 분리된 외부 경로에 사용자 데이터와 비밀정보 저장 |
| 보고서 모듈 | 동일한 모델·해석 객체에서 검토표와 계산서 생성 |
| 검증 하네스 | 기능, 수치 평형, 문서, 보안, 마이그레이션과 배포 회귀검사 |

현재 배포 형식은 정식 설치 프로그램이 아니라 **portable ZIP**이다. 코드서명, 자동 업데이트와 Windows installer 자격은 아직 완료되지 않았다.

## 6. 데이터·보안·승인 구조

Phase 12에서는 내부 파일럿 운영을 막던 핵심 위험을 다음과 같이 보완했다.

- 웹에 공개되는 파일을 명시적 allowlist로 제한
- 소스코드, `.git`, 서버 설정, 사용자 데이터, 비밀정보와 임시 파일의 HTTP 노출 차단
- 설치 폴더와 사용자 상태·업로드·백업 폴더 분리
- 기존 데이터 무손실 이전과 비밀키 교체 절차 구현
- 이전 비밀키로 발급된 토큰의 사용 차단
- 인증 실패, 요청 크기, 저장용량과 주요 자원 사용 제한
- 보안 헤더와 허용 Origin 정책 적용
- 승인 대상을 실제 존재하는 리비전과 콘텐츠 해시에 결합
- 승인 후 새 리비전이 생기면 기존 승인을 stale 상태로 전환
- 중복 서버 실행, 데이터 잠금 충돌과 부분 마이그레이션의 거짓 성공 차단
- 백업 전후 파일 목록·크기·SHA-256 일치 확인

로컬 파일럿은 기본 가입 차단을 유지하고, 초기 bootstrap이 필요한 제한된 시간에만 명시적으로 가입을 허용해야 한다. 서버는 외부 주소가 아닌 loopback에만 연결해야 한다.

## 8. 실용화 가능 범위

### 지금 가능한 범위

1. 교육·연구용 3D 구조해석 시연
2. 기본 frame/truss 모델의 선형 탄성 거동 확인
3. 초기 구조계획과 부재 크기의 비교 검토
4. 하중조합별 부재력·변형·반력·지배조합 검토
5. 예비 응력·세장비·처짐 스크리닝
6. 동일 모델에서 계산 근거와 보고서 생성
7. 한 명 또는 통제된 소수 담당자가 단일 Windows PC에서 수행하는 내부 파일럿

### 아직 허용되지 않는 범위

1. 프로그램 결과만으로 부재를 최종 확정하는 행위
2. 구조계산서의 책임기술자 검토를 생략하는 행위
3. 인허가 또는 최종 납품 결과의 자동 승인
4. LAN, VPN 또는 인터넷에 서버를 직접 공개하는 운영
5. 여러 조직이 사용하는 SaaS 또는 다중 테넌트 서비스
6. preliminary 또는 unsupported 결과를 최종 공학 근거로 승격하는 행위

## 9. 성능과 규모 기준

현재 자동 성능 증빙에 따른 frame 모델 규모의 대략적인 운영 기준은 다음과 같다.

- 약 1,000개 부재까지: 일반적인 대화형 사용 범위
- 2,000개 부재 이상: 프로젝트별 성능·정확도 검토 필요
- 약 4,000개 부재: 장시간 전용 검증 후 사용

이 값은 모든 PC와 모든 모델 유형에 대한 보장치가 아니다. 부재 수뿐 아니라 구속조건, 해석 종류, 조합 수, 결과 저장량과 브라우저 그래픽 부하에 따라 실제 성능이 달라진다.

## 10. 남아 있는 핵심 한계

### 공학 검증

- Phase 10 외부 교차검증은 완료되지 않았고 `externallyCrossValidated=false`다.
- 외부 검증 항목 중 현재 적격 green 근거는 제한적이다.
- Phase 11 보고서의 독립 공학 정답 판정 상한은 `CONDITIONAL_PASS`다.
- 최종 구조설계 전이는 `designTransferAllowed=false`다.

## 11. 다음 개발 우선순위

1. **외부 공학 교차검증 완결**  
   상용 해석기 결과와 독립 수계산을 적격 원본 증빙으로 확보하고, 핵심 선형·P-Delta·모달·좌굴·고급 요소의 허용오차를 확정한다.

2. **실제 사무소 파일럿 수행**  
   대표 프로젝트를 선정해 기존 계산 절차와 병행 검산하고, 모델링 시간·오류 유형·수정 이력·보고서 활용성을 측정한다.

3. **정식 제품 패키징**  
   Windows installer, 코드서명, 업데이트·복구와 사용자별 설정 안내를 하나의 배포 흐름으로 통합한다.

4. **LAN·다중사용자 아키텍처 별도 설계**  
   로컬 서버를 단순히 외부 주소에 연결하지 말고, 운영 DB·권한·TLS·감사·백업·관제 요구사항을 새 보안 게이트로 정의한다.

5. **예비 기능과 검증 기능의 화면 분리 강화**  
   stable, review-required, preliminary, unsupported 상태가 화면·API·보고서에서 동일하게 보이도록 유지한다.

## 12. 운영 시 필수 원칙

- 배포 ZIP의 SHA-256을 확인한 뒤 사용한다.
- 설치 파일과 사용자 데이터 폴더를 분리한다.
- loopback-only 설정을 임의로 해제하지 않는다.
- 기본 가입 차단을 유지한다.
- 프로젝트 변경 전후와 중요 승인 전에 백업을 생성한다.
- 새 리비전이 생성되면 기존 승인 상태를 다시 확인한다.
- preliminary·unsupported 경고를 보고서에서 제거하지 않는다.
- 최종 판단은 원본 입력, 독립 검산과 책임기술자 검토를 거친다.

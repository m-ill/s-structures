# Phase30 — 결합과 전역 수렴

2026-09-14 · 계획 v2 · **[Phase29](../phase29/README.md) 완료됨, 착수 가능**

## v1 계획의 사실 오류 두 개를 먼저 정정한다

계획을 세우기 전에 코드를 실측했고, v1이 틀린 곳이 두 군데 있었다.

**① "프레임 세분화 결과에 `convergenceVerified: false`가 그대로 표기된다"** — 아니다. `convergenceVerified`는 **메시 세분화 수렴**이고 이미 구현·판정된다. `rcSpliceModelSolve.js:71`이 세분 전후 비교값이 허용오차 이하일 때 `true`로 올린다. `false`는 미구현 표시가 아니라 **아직 비교가 성립하지 않은 경로의 정직한 초기값**이다.

**② "후보 1200 · 200,000 work-unit"** — 그런 상한은 없다. 실제 상한은 `practicalDesignLimits.js`에 있다:

```
maxCandidates 16 · maxCandidateMillis 10,000 · maxEvaluationMillis 120,000
maxMembers 300 · maxStationsPerSet 6,300
```

전역 반복의 비용 상한은 이 값들과 같은 자리에, 같은 성격으로 붙어야 한다.

## 이미 있는 것 — 반복 엔진을 새로 만들지 않는다

`runFlexuralIteration`은 **범용 고정점 루프**다. 새로 설계할 것이 없다.

```js
runFlexuralIteration(source, { calculateProfiles, maxIterations=20, tolerance=1e-6, signal })
```

가진 것:

| 기능 | 구현 |
| --- | --- |
| 잔차 두 종 | `profileResidual`(설계량 변화), `displacementResidual`(응답 변화) |
| 입력 무효화 | `sourceModelHash` 비교 → `STALE_FLEXURAL_ITERATION` |
| 취소 | `signal.aborted` → `FLEXURAL_ITERATION_CANCELLED` |
| 상한 | `maxIterations` 1~30, `tolerance` ≤ 1e-2, 범위 밖이면 즉시 throw |
| 이력 | 반복마다 `trace` 적재 |
| 2차 해석 연동 | `direct` P-Δ 경로에서 미수렴 시 실패 전파 |

`runRcCoupledIteration`, `runKdsSecondOrderIteration`, `runRcServiceIteration`이 모두 이 루프를 감싼다. **콜백(`calculateProfiles`)만 갈아끼우는 구조**다.

## 비어 있는 것 — 고리가 닫히지 않는다

현재 루프가 반복하는 것은 **강성 프로파일**(균열단면 유효강성)이다. 단면 치수가 아니다.

```
현재:   단면(고정) → 강성 프로파일 → 부재력 → 강성 프로파일 → ...   ✅ 수렴 판정됨

비어 있음:
        단면 치수 변경 → 자중 → 하중 → 부재력 → 단면
                      ↘ 지진질량 → 밑면전단 → 부재력 → 단면
```

되먹임이 **데이터 모델에는 이미 있다** — `massSource`의 `includeSelfWeight`가 자중을 지진질량에 넣는다. 단면이 바뀌면 자중이, 자중이 바뀌면 질량이, 질량이 바뀌면 밑면전단이 바뀐다. 그런데 **루프 안에서 자중과 질량을 다시 만들지 않는다.**

그래서 Phase30은 "반복을 구현한다"가 아니라 **"고리의 끊어진 변을 잇고, 닫힌 고리의 수렴을 판정한다"**이다.

## 착수 전 오너 결정 두 가지

### 결정 1 · 무엇을 "수렴했다"로 볼 것인가

권고: **둘 다 요구하되 각각 따로 보고한다.**

```
converged = (부재력 잔차 ≤ tol) AND (단면·배근이 직전 반복과 동일)
```

한쪽만으로는 안 되는 이유가 분명하다.

- **부재력 잔차만** 보면, 힘은 거의 안 변하는데 **이산 규격 선택이 두 값 사이를 계속 튀는** 상태(D22 ↔ D25)를 수렴으로 읽는다. 실무 설계에서 실제로 흔한 상태다.
- **단면 무변화만** 보면, 애초에 아무것도 재설계되지 않은 1회차가 "수렴"이 된다. 되먹임이 끊긴 것과 수렴한 것을 구분하지 못한다.

둘을 **AND로 묶되 결과에는 따로 싣는다.** 힘은 수렴했는데 단면이 튄다는 사실 자체가 설계자에게 필요한 정보다.

### 결정 2 · 비용 상한

권고: 기존 상한과 같은 자리(`practicalDesignLimits.js`)에 붙인다.

```
maxGlobalIterations      기본 6, 상한 12
maxGlobalIterationMillis 재사용: maxEvaluationMillis 120,000
```

**전역 반복 1회 = 전체 해석 한 사이클**이라 부재 단위 반복과 비용 차수가 다르다. 부재 루프의 `maxIterations=20`을 그대로 쓰면 안 된다. 300부재 모델에서 6회면 해석 6회 + 설계 6회다.

상한에 걸리면 **실패가 아니라 미수렴 보고**다. 이건 이 저장소가 이미 쓰는 방식이다.

**두 결정이 나오기 전에도 M0·M1은 진행할 수 있다.** 되먹임 경로 식별은 판정 기준과 무관하기 때문이다. M2 이후가 결정에 걸린다.

## 마일스톤

### M0 · 기록 정정과 기준선 (결정 불필요)

1. 위의 사실 오류 두 건을 정정한다(이 문서로 완료).
2. 현재 루프가 **무엇을 반복하고 무엇을 반복하지 않는지**를 측정해 기준선으로 남긴다 — 반복 중 재생성되는 양과 고정되는 양의 목록.
3. 단면을 바꿨을 때 자중·질량·밑면전단이 실제로 따라 변하는지 **실측 시험**을 하나 만든다. 지금은 안 변한다는 것을 고정하는 시험이다(적색 아님, 현행 동작 기록).

**완료 조건** — "무엇이 되먹임되고 무엇이 안 되는지"가 시험으로 고정된다.

### M1 · 되먹임 경로 선언 (결정 불필요)

`inputIdentity`/`stale`은 "입력이 바뀌면 이전 결과 무효"를 이미 처리하지만 **어디까지 번지는지**는 표현하지 않는다.

1. 변경 종류 → 무효화 대상의 선언적 표를 만든다. Phase29에서 쓴 `CHECK_REFERENCES` 형태를 따른다 — 값·범위·근거가 한 행에 있는 패턴.

```
단면 치수  → 자중, 지진질량, 밑면전단, 강성, 부재력, 층간변위
배근       → 강성(균열단면), 부재력, 층간변위
재료 강도  → 강성, 강도판정
```

2. 표를 읽어 **변경 하나가 무엇을 무효화하는지** 반환하는 함수를 만든다. 계산하지 않고 범위만 답한다.
3. 선언과 실제 재계산이 어긋나는지 검사하는 게이트를 붙인다 — Phase28의 드리프트 검사와 같은 비대칭 원칙(선언이 넓은 쪽은 허용, 좁은 쪽은 실패).

**완료 조건** — 단면 변경이 지진질량까지 번진다는 사실이 **자료구조에 있다.**

### M2 · 고리 닫기 (결정 1 필요)

`runFlexuralIteration`의 콜백 계약을 넓혀 **단면 치수 변경**을 받는다. 루프 자체는 건드리지 않는다.

1. 반복 안에서 현재 단면으로 **자중을 재생성**한다. 기존 자중 하중을 갱신하는 것이지 중복 추가가 아니다 — `loadAudit`의 `double-self-weight-candidate` 검사가 이미 이 실수를 잡는다.
2. `massSource.includeSelfWeight`가 켜져 있으면 **지진질량을 재생성**하고 밑면전단을 다시 스케일한다.
3. 잔차에 **설계량 변화**를 추가한다(결정 1의 두 번째 항). 기존 `profileResidual`과 별도 필드로 둔다.

**완료 조건** — 보를 키우면 자중이 늘고 부재력이 늘어 다음 반복 입력이 실제로 달라진다. 그 변화가 `trace`에 보인다.

### M3 · 진동 감지와 종료 보장 (결정 1·2 필요)

보를 키우면 자중이 늘어 더 키워야 하는 진동이 **원리적으로 가능하다.** 실무는 이산 규격과 판단으로 감쇠시킨다. 자동화하려면 그 감쇠를 명시해야 한다.

1. **진동 감지** — 직전 상태를 재방문하면 순환이다. 반복마다 설계 상태의 해시를 쌓고 재방문을 검출한다. 잔차 크기로 추정하지 않는다.
2. 순환을 만나면 **중단하고 순환 구간을 보고한다.** 완화계수로 억지 수렴시키지 않는다 — 두 규격 사이의 순환은 "둘 다 성립하지 않는다"가 아니라 "판단이 필요하다"이고, 그 판단은 설계자의 것이다.
3. 반복 수 상한과 시간 상한(결정 2)으로 **종료를 보장**한다.

**완료 조건** — 수렴, 순환, 상한 도달이 서로 다른 상태로 구분되어 보고된다.

### M4 · 정직한 보고 (결정 1 필요)

**중단은 실패가 아니다.** 수렴하지 않으면 수렴하지 않았다고 보고하는 것이 옳다.

1. 반환 상태를 넷으로 구분한다.

| 상태 | 뜻 |
| --- | --- |
| `CONVERGED` | 두 판정 모두 충족 |
| `FORCE_CONVERGED_SECTION_OSCILLATING` | 힘은 수렴, 규격이 튄다 |
| `CYCLE_DETECTED` | 설계 상태가 순환 |
| `ITERATION_LIMIT_REACHED` | 상한 도달, 판정 미완 |

2. 모든 상태에서 `designTransferAllowed: false`를 유지한다. 수렴은 승인이 아니다.
3. 미수렴 결과가 보고서와 도면 경로로 **조용히 흘러가지 않게** 막는다. `rcSplicePolicy`가 이미 `convergenceVerified`로 같은 일을 하므로 그 자리를 따른다.

**완료 조건** — 미수렴 모델이 설계 전달 경로에 오르지 못하고, 왜 못 오르는지가 사용자에게 보인다.

### M5 · 등록과 게이트

1. 비용 상한을 `practicalDesignLimits.js`에 등록(결정 2).
2. 새 시험을 `p30-` 이름으로 만들면 Phase29에서 상한을 없앤 러너가 자동 편입한다.
3. 되먹임 선언 드리프트 검사를 게이트에 편입.

## 이 페이즈가 하지 않는 것

- **수렴을 보장한다고 주장하지 않는다.** 목표는 수렴 여부를 판정하고 정직하게 보고하는 것이다. 수렴하지 않는 설계 문제는 실제로 존재한다.
- **완화계수로 억지 수렴시키지 않는다.** 순환은 보고 대상이지 감쇠 대상이 아니다.
- **새 반복 엔진을 만들지 않는다.** `runFlexuralIteration`의 콜백 계약을 넓힐 뿐이다.
- **판·쉘 FEM의 직사각 패널 정확도 결함을 다루지 않는다.** Phase29 M3가 그것에 의존하지 않았듯 여기서도 의존하지 않는다.

## 경계

전역 수렴 판정은 계약 확대이지 구조설계 승인이 아니다. `CONVERGED`가 나와도 `designTransferAllowed`는 false이고 외부 독립 검증은 별개다.

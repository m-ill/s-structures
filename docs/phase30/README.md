# Phase30 — 결합과 전역 수렴 (계획 골격)

2026-09-14 · 골격 v1 · **[Phase29](../phase29/README.md) 완료가 선행 조건**

## 왜 필요한가

부재·구간 단위 반복은 이미 수렴 판정까지 자동이다.

```
rcCoupledIteration   maxIterations=20, tolerance=1e-6, converged, trace
flexuralIteration / kdsSecondOrderIteration / rcServiceIteration
```

비어 있는 것은 **건물 전체 규모의 반복**이다. 현재 코드도 이를 숨기지 않는다 — 프레임 세분화 결과에 `convergenceVerified: false`가 그대로 표기된다.

문제의 형태는 이렇다. 보 단면을 바꾸면

```
단면 → 자중 → 하중 → 부재력 → 층간변위
                  ↘ 지진질량 → 밑면전단 → 부재력 → 단면
```

되먹임이 닫힌 고리를 이룬다. 지금은 각 변을 계산할 수 있지만 **고리 전체가 수렴하는지는 판정하지 않는다.**

## 다루어야 할 세 가지

### 1. 되먹임 경로의 식별

어떤 변경이 무엇을 무효화하는지 선언되어야 한다. `inputIdentity`/`stale`이 이미 "입력이 바뀌면 이전 결과 무효"를 처리하지만, **어디까지 번지는지**는 표현하지 않는다. 단면 변경이 지진질량까지 번진다는 사실이 자료구조에 없다.

### 2. 진동 억제

보를 키우면 자중이 늘고 힘이 늘어 더 키워야 하는 진동이 원리적으로 가능하다. 실무는 이산 규격과 판단으로 감쇠시킨다. 자동화하려면 그 감쇠를 명시해야 한다 — 완화계수, 단조 수렴 조건, 또는 진동 감지 후 중단.

**중단은 실패가 아니다.** 수렴하지 않으면 수렴하지 않았다고 보고하는 것이 옳다. 이 저장소가 이미 쓰는 방식이다.

### 3. 종료 보장과 비용

후보 탐색은 작업량 상한으로 **종료를 보장**한다(후보 1200 · 200,000 work-unit). 전역 반복도 같은 성격의 상한이 필요하며, 한 번의 전역 반복은 전체 해석 한 사이클이므로 비용이 다르다.

## 착수 조건

1. Phase29 완료 — 슬래브·벽이 검사 경로에 없으면 전역 반복이 닫히지 않는다.
2. **수렴 판정 기준에 대한 오너 결정.** 무엇이 "수렴했다"인가: 부재력 변화율, 단면 변화 없음, 아니면 둘 다. 이건 공학 판단이라 먼저 정해야 한다.
3. 비용 상한 결정 — 전역 반복 몇 회까지 허용하는가.

## 이 페이즈가 하지 않는 것

수렴을 보장한다고 주장하지 않는다. 목표는 **수렴 여부를 판정하고 그 결과를 정직하게 보고하는 것**이다. 수렴하지 않는 설계 문제는 실제로 존재한다.
